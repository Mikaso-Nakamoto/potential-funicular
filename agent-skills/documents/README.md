# Documents — Word, PowerPoint, Excel и PDF

Категория про **офисные форматы как контейнеры**: их разбор, правку и сборку. Не «сгенерировать текст», а реально открыть `.docx`, поменять стиль, пересобрать `.pptx` со слайдами, посчитать формулы в `.xlsx`, вытащить таблицу из PDF.

**4 навыка.** Skill-тексты на английском (как в апстриме), описания — на русском.

## Когда подключать

| Задача | Навык |
| --- | --- |
| Создать, прочитать, отредактировать `.docx` или `.dotx`; трекинг правок, комментарии, слияние прогонов | [`docx`](docx/SKILL.md) |
| Слайды `.pptx` / `.potx`: собрать колоду, разметить layouts, вставить изображения, заметки | [`pptx`](pptx/SKILL.md) |
| Таблицы `.xlsx` / `.csv`: формулы, форматирование, сводки, чтение чужих файлов | [`xlsx`](xlsx/SKILL.md) |
| PDF: текст и таблицы, склейка и разделение, формы, заполнение, OCR-сценарии | [`pdf`](pdf/SKILL.md) |

## Что внутри

- **`docx`** — работа через `python-docx` плюс собственный `scripts/office/`: `validate.py` (валидация OOXML по схемам), `soffice.py` (конвертация через LibreOffice), `comment.py` (комментарии), `merge_runs.py` (склейка прогонов после правок), `accept_changes.py`. Есть `scripts/templates/` для генерации с нуля.
- **`pptx`** — сборка колод по layout-ам, работа с master-слайдами, изображениями и заметками; в `scripts/` те же OOXML-валидаторы.
- **`xlsx`** — формулы, стили, объединения, чтение существующих книг без потери форматирования; openpyxl-обвязка.
- **`pdf`** — `REFERENCE.md` (20 КБ) по всем сценариям и `FORMS.md` по формам; извлечение таблиц, разбиение, наложение.

## Требования

- Python 3.10+
- `pip install python-docx openpyxl python-pptx pypdf` (по навыку)
- LibreOffice (`soffice`) для конвертации и рендера — часть скриптов опирается на него

## Лицензии и атрибуция

Все четыре навыка — [anthropics/skills](https://github.com/anthropics/skills), **Apache-2.0** (см. `LICENSE.txt` в каждой папке).

Внутри `scripts/office/schemas/` лежат официальные OOXML-схемы ECMA-376 (~1 МБ) — они и дают основную массу категории. Это нормативный контент стандарта, а не код, поэтому папка тяжёлая; удалять её нельзя, без неё не работает `validate.py`.

## Почему отдельная категория

В библиотеке до этого не было ничего про офисные форматы: `ui/slides` делает **HTML**-презентации, `design-logic/copywriting` пишет текст, но ни один навык не открывал `.docx` и не собирал `.pptx`. Это не пересечение — это дыра, которая закрылась.
