# AI Integration — API, MCP-серверы и тестирование веб-приложений

Категория про то, как **подключить агента к внешнему миру**: собрать MCP-сервер, работать с Claude API из любого языка, проверить своё веб-приложение браузером.

**3 навыка.**

## Когда подключать

| Задача | Навык |
| --- | --- |
| Вызвать Claude API / Anthropic SDK: модели, цены, стриминг, tool use, кеширование, счёт токенов | [`claude-api`](claude-api/SKILL.md) |
| Написать MCP-сервер, чтобы LLM получила доступ к внешнему сервису | [`mcp-builder`](mcp-builder/SKILL.md) |
| Протестировать локальное веб-приложение через Playwright: клики, формы, проверка UI | [`webapp-testing`](webapp-testing/SKILL.md) |

## Что внутри

- **`claude-api`** — самая большая часть (2.2 МБ): готовые примеры на **9 языках** (`python`, `typescript`, `go`, `java`, `csharp`, `php`, `ruby`, `curl`, плюс `shared` с общими типами). `SKILL.md` на 104 КБ покрывает model ids, параметры, стриминг, tool use, MCP, агентов, prompt caching, подсчёт токенов. Это справочник, а не туториал: ищется по ключевому слову, читается по разделу.
- **`mcp-builder`** — как проектировать MCP-серверы, которые модели реально удобно вызывать: описание инструментов, схемы аргументов, обработка ошибок, ресурсы и промпты. Плюс `reference/` и `scripts/`.
- **`webapp-testing`** — Playwright-обвязка для проверки локального приложения: навигация, проверка отрисованного UI, отладка фронтенда. Полезен, когда `workflow-progress-screenshots` не хватает и нужен полноценный браузерный сценарий.

## Требования

- `claude-api`: API-ключ, ключи передаются из окружения — **в репозитории секретов нет**
- `mcp-builder`: Node.js или Python в зависимости от выбранного SDK
- `webapp-testing`: `npx playwright install` (браузеры качаются отдельно, в репозитории их нет)
