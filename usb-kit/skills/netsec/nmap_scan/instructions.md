# Директива: netsec/nmap_scan

## Когда вызывать

- Нужен структурированный список живых хостов/открытых портов по явно указанной цели.
- Результаты пойдут дальше по пайплайну (инвентаризация, приоритизация, отчёт).
- Есть подтверждённое разрешение на сканирование этой цели.

## Как строить параметры

- `target` — одна цель за вызов (IP, CIDR или имя). Несколько целей = несколько вызовов.
- `ports` — сужайте скоуп осознанно: сначала топ-порты (без параметра), затем точечно.
- `scripts` — начинайте с `default`; вулн-скрипты (`vuln`) только в рамках согласованных работ.
- `timing` — держите T3; T4/T5 создают нагрузку и шумят в IDS.
- `timeout` — поднимайте для больших CIDR, не более 900 секунд.

## Как читать результат

- `status=success`: поле `hosts[]` — источник истины; `scan.command` можно цитировать в отчёте.
- `status=error` с `missing_dependency`: на машине нет nmap — сообщите оператору, не придумывайте данные.
- `status=timeout`: сузьте порты/таргет и повторите; частичные данные не возвращаются.

## Запрещено

- Расширять скоуп самостоятельно (соседние подсети, «интересные» хосты рядом).
- Просить агрессивные/эвазивные флаги: профиль намеренно безопасный (-sT, --open).
- Интерпретировать отсутствие ответа как «хост безопасен».

Для глубоких методик (обход IDS, OS-фингерпринт, NSE-сценарии) сначала читайте маркдаун-скилл
Pi `scanning-network-with-nmap-advanced`, затем формулируйте запрос оператору.
