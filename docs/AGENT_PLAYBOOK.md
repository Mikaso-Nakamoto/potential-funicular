# Playbook для агента-настройщика (Gemini Antigravity и т.п.)

Здесь — готовые блоки промптов. Копируете блок, вставляете агенту, он выполняет
рутинy. Порядок блоков = порядок настройки. Каждый блок самодостаточен: в нём
есть цель, шаги и критерий готовности.

---

## Общие правила для агента (вставьте один раз в начале сессии)

```
Ты настраиваешь VK-бота записи на массаж. Проект лежит в ~/massage-bot
(клон репозитория Mikaso-Nakamoto/potential-funicular).

Жёсткие правила:
1. НЕ коммить и не публикуй файлы .env и config.toml — в них секреты и личные
   данные. Они уже в .gitignore, проверь это.
2. НЕ переписывай модули bot/*.py. Твоя задача — настройка (config.toml, .env,
   systemd, cron) и диагностика, а не разработка.
3. Внешние зависимости не нужны: бот работает на стандартной библиотеке
   Python 3.11+. НЕ ставь pip-пакеты, кроме tomli и только если Python < 3.11.
4. После любого изменения config.toml или .env перезапускай службу:
   sudo systemctl restart massage-bot
5. После любых изменений прогоняй проверки:
   python3 scripts/doctor.py --all
   python3 tests/run_all.py     (ожидаемый результат: 43 прошло, 0 упало)
6. Не запускай бота вручную, если уже работает служба systemd — два экземпляра
   дают дубли ответов. Проверь: pgrep -af "bot.main"
7. Все действия с ВКонтакте делай от имени сообщества; личный токен пользователя
   не нужен и не запрашивай его.
8. Если что-то не получается — не меняй код, а покажи вывод doctor и журнал:
   journalctl -u massage-bot -n 100 --no-pager
Документация: docs/VK_SETUP.md, docs/DEPLOY.md, docs/TROUBLESHOOTING.md.
```

## Блок 1. Установка кода

```
Установи бота в ~/massage-bot:
1. Проверь версии: python3 -V (нужно 3.11+), git --version.
2. Если Python < 3.11 — поставь python3-tomli (или python3.11), объясни выбор.
3. Клонируй репозиторий:
   git clone https://github.com/Mikaso-Nakamoto/potential-funicular.git ~/massage-bot
   Если каталог уже существует — сделай git pull и сообщи о локальных изменениях.
4. Проверь, что нет внешних зависимостей: pip freeze не нужен, просто убедились,
   что requirements.txt пустой/служебный.
5. Прогони тесты: python3 tests/run_all.py
Готово, когда: каталог существует, тесты — «43 прошло, 0 упало».
Выведи список файлов проекта и результат тестов.
```

## Блок 2. Собрать данные у человека

```
Прежде чем править конфиг, задай мне вопросы и дождись ответов. Ничего не
выдумывай сам. Спроси:
1. Имя мастера и город (для приветствия и часового пояса).
2. Услуги: название, длительность в минутах, цена. Сколько угодно пунктов.
3. Рабочие дни и часы по каждому дню, есть ли обеденный перерыв.
4. Сколько минут нужно между сеансами (подготовка) и за сколько часов минимум
   можно записаться.
5. Телефон, WhatsApp, Telegram, личная страница ВК, точный адрес, как найти
   кабинет.
6. За сколько часов напоминать клиенту и мастеру; нужно ли утреннее резюме
   списка записей и во сколько.
7. За сколько часов клиент ещё может отменить запись сам.
8. Тон общения с клиентами: официально («Вы») или тепло и просто.
Ответы оформи таблицей и покажи мне на утверждение ДО правки файлов.
```

## Блок 3. Заполнить config.toml

```
Создай ~/massage-bot/config.toml из config.example.toml и заполни его данными,
которые я утвердил в прошлом шаге.
Требования:
- секция [bot]: timezone — по городу мастера (например Europe/Moscow,
  Europe/Samara, Asia/Yekaterinburg). Проверь, что такой часовой пояс
  существует в системе.
- [[services]]: по одной на услугу, id — короткое латиницей без пробелов,
  duration в минутах, price числом.
- [schedule]: work_days и [schedule.hours] по фактическому графику; пустой
  список часов = выходной. slot_minutes — шаг сетки, buffer_minutes — пауза
  между сеансами, min_notice_minutes — минимальный запас до сеанса,
  max_days_ahead — глубина записи.
- [contacts]: все живые контакты (телефон обязателен), адрес и как найти.
- [reminders] и [policy]: по моим ответам.
- [texts]: если я просил другой тон — перепиши greeting, request_created,
  approved_client, reminder_client. Плейсхолдеры в {} НЕ трогай и не удаляй.
  Список плейсхолдеров: docs/TEXTS.md
- Ключ сообщества и id НЕ пиши в config.toml — только в .env.
После правки выполни: python3 scripts/doctor.py --slots
и покажи мне, какие окна увидит клиент на ближайшие 5 дней по каждой услуге.
Спроси, устраивает ли меня сетка.
```

## Блок 4. Настроить ВКонтакте

```
Помоги настроить сообщество ВКонтакте. Действуй по docs/VK_SETUP.md.
1. Спроси у меня: есть ли сообщество, его адрес (club…/screen_name) и есть ли
   уже ключ доступа сообщества.
2. Если сообщества нет — дай пошаговую инструкцию создать (тип «Бизнес»),
   включить «Сообщения сообщества» для всех пользователей и задать
   приветственный текст.
3. Дай инструкцию создать ключ доступа сообщества с правами «сообщения
   сообщества» и «управление сообществом».
4. Попроси у меня group_id (число после club) и ключ. Запиши их в ~/massage-bot/.env:
   VK_GROUP_ID=…, VK_GROUP_TOKEN=…
   Выполни chmod 600 .env и убедись, что .env есть в .gitignore.
5. Включи Long Poll API: python3 scripts/vk_setup.py, затем --apply.
   Если API откажет из-за прав — выведи ручные шаги из docs/VK_SETUP.md.
6. Напомни мне, что мастер должен один раз написать своему сообществу, иначе
   ВК не даст боту писать первым.
Готово, когда: doctor.py --api показывает ✅ по сообществу, Long Poll и
доставке тестового сообщения. Покажи вывод.
```

## Блок 5. Узнать id мастера и проверить доставку

```
Определи vk_id мастера и пропиши его в ADMIN_VK_IDS:
1. Запусти бота вручную на короткое время: python3 -m bot.main
2. Попроси меня написать любое сообщение в сообщество со страницы мастера.
3. Останови бота (Ctrl+C) и выполни: python3 scripts/doctor.py --whoami
4. Впиши найденный id в .env как ADMIN_VK_IDS=<id> (если мастеров несколько —
   через запятую).
5. Проверь доставку: python3 scripts/doctor.py --send-test
Готово, когда: в личные сообщения мастера пришло тестовое сообщение, а doctor
не показывает предупреждений про ADMIN_VK_IDS. Покажи вывод --whoami.
```

## Блок 6. Поставить как службу

```
Установи бота как службу systemd по docs/DEPLOY.md шаг 6:
1. Скопируй systemd/massage-bot.service в /etc/systemd/system/.
2. Подставь реального пользователя (whoami) и путь (pwd) в User,
   WorkingDirectory и ReadWritePaths.
3. daemon-reload, enable --now, покажи status.
4. Настрой ноутбук как сервер: отключи уход в сон при закрытии крышки
   (HandleLidSwitch=ignore в /etc/systemd/logind.conf + mask sleep/suspend/
   hibernate/hybrid-sleep), проверь, что NTP включён (timedatectl).
5. Убедись, что ручной экземпляр бота не запущен: pgrep -af "bot.main"
6. Покажи последние 30 строк журнала: journalctl -u massage-bot -n 30 --no-pager
Готово, когда: статус active (running), в логе «Слушаю сообщения сообщества»,
автозапуск включён, сон отключён.
```

## Блок 7. Сквозная проверка

```
Проведи сквозную проверку боевого бота. Пиши мне, что делать, и проверяй лог.
1. Со своей (не мастерской) страницы напиши сообществу «привет».
   Ожидание: пришло меню с кнопками «📅 Записаться», «📋 Мои записи»,
   «💰 Услуги и цены», «📞 Связаться», «ℹ️ О мастере».
2. Проверь раздел «💰 Услуги и цены»: услуги и цены совпадают с config.toml.
3. Проверь «📞 Связаться»: видны телефон, WhatsApp, страница ВК, адрес.
4. Пройди запись до конца: услуга → дата → время → имя → телефон →
   «Без комментария» → «Отправить заявку».
   Ожидание: клиенту «✅ Заявка отправлена», мастеру — карточка заявки с
   кнопками «Подтвердить/Отклонить/Перенести» и ссылкой на диалог с клиентом.
5. Со страницы мастера нажми «✅ Подтвердить».
   Ожидание: клиенту пришло подтверждение с адресом; мастеру — подтверждение;
   в логе нет ошибок.
6. Проверь «📋 Мои записи» у клиента и команду /today у мастера.
7. Отмени запись клиентом и убедись, что мастеру пришло уведомление, а слот
   снова свободен (doctor.py --slots).
8. Прогони unit-тесты: python3 tests/run_all.py (43/0).
Составь отчёт по пунктам: что прошло, что нет, приложи строки лога по каждому
замечанию.
```

## Блок 8. Резервные копии и наблюдение

```
Настрой ежедневную резервную копию базы:
1. Проверь, что ./scripts/backup_db.sh работает и создаёт backups/*.sqlite3.gz
2. Добавь в cron текущего пользователя строку на 21:30 ежедневно:
   30 21 * * * cd /home/USER/massage-bot && ./scripts/backup_db.sh >> backups/backup.log 2>&1
3. Покажи crontab -l и последние строки backups/backup.log
4. Объясни мне в двух предложениях, как восстановить базу из копии.
5. Предложи способ вывозить копии с ноутбука (флешка/облако/второй компьютер) —
   но ничего не настраивай без моего согласия.
```

## Блок 9. Передать мастеру

```
Подготовь передачу мастеру (человеку без технических знаний):
1. Покажи docs/ADMIN_GUIDE.md и проверь, что все команды из таблицы реально
   работают у нашего бота (протестируй /today, /week, /pending, /stats, /off,
   /block, /say, /help).
2. Сформируй короткую шпаргалку на одну страницу: что делать при новой заявке,
   как закрыть день, как перенести запись, куда писать если сломалось.
3. Выведи ссылку для клиентов (https://vk.me/<адрес сообщества>) и подскажи,
   где её разместить: статус сообщества, закреплённый пост, личная страница,
   QR-код в кабинете.
4. Перечисли, что мастеру нужно делать регулярно: отвечать на заявки, смотреть
   утренний список, раз в месяц проверять, что ноутбук не перезагрузился и бот
   работает (systemctl status massage-bot).
```

## Быстрая шпаргалка команд

```bash
python3 scripts/doctor.py --all       # вся диагностика
python3 scripts/doctor.py --slots     # какие окна видит клиент
python3 scripts/doctor.py --whoami    # vk_id людей, писавших боту
python3 scripts/doctor.py --send-test # тест доставки мастеру
python3 scripts/vk_setup.py --apply   # включить Long Poll и события
python3 scripts/demo.py --auto        # сценарий без ВК, в терминале
python3 tests/run_all.py              # 43 теста
python3 -m bot.main --check           # проверить конфиг
python3 -m bot.main --once            # один проход воркера
journalctl -u massage-bot -f          # живой лог
./scripts/backup_db.sh                # резервная копия
```

## Чего агенту делать НЕ надо

- не трогать `bot/*.py` ради настройки (всё настраивается через `config.toml`);
- не менять `[bot] timezone` после появления записей в базе;
- не хранить ключ сообщества в `config.toml`, в коде или в переписке;
- не удалять `data/` и файлы `-wal`/`-shm` при работающем боте;
- не запускать второй экземпляр бота «для проверки»;
- не подключать платные сервисы и рассылки без явного согласия владельца.
