# Если что-то пошло не так

Первое действие почти всегда одно:

```bash
python3 scripts/doctor.py --all
journalctl -u massage-bot -n 100 --no-pager     # если запущен как служба
```

---

## Бот вообще не отвечает

| Причина | Как проверить | Что делать |
|---|---|---|
| Бот не запущен | `systemctl status massage-bot` | `sudo systemctl start massage-bot` |
| Ноутбук уснул | время в логе прерывается | [DEPLOY.md шаг 7](DEPLOY.md#7-ноутбук-как-сервер-не-давать-ему-засыпать) |
| Нет интернета | `ping -c 2 api.vk.com` | проверить роутер/кабель |
| Нет ключа или id | `doctor --all` покажет ❌ | заполнить `.env` |
| Не включён Long Poll | `python3 scripts/vk_setup.py` | `--apply` или включить руками |
| Пишут в беседу, а не в личку сообщества | в логе «Сообщение из беседы пропущено» | бот работает только в личных сообщениях сообщества |

В логе должно быть `← <имя> (<id>): <текст>` на каждое входящее сообщение.
Если такой строки нет — проблема между ВК и ботом (ключ/Long Poll/сеть), а не в
логике.

## «Ключ сообщества отклонён» / error 5

- Ключ должен быть **ключом сообщества** (Управление → Работа с API → Ключи
  доступа), а не личным токеном пользователя.
- Сообщество в `VK_GROUP_ID` должно совпадать с тем, где создан ключ.
- У ключа должно быть право **«сообщения сообщества»**.
- Ключ показывается один раз: если не скопировали — создайте новый.

## «Нет связи с api.vk.com»

```bash
ping -c 2 api.vk.com
timedatectl                    # время должно быть точным
```

Неверное системное время ломает HTTPS-соединение. Лечится:
`sudo timedatectl set-ntp true`.

## Кнопки у мастера не нажимаются / ничего не происходит

Скорее всего не включено событие `message_event`:

```bash
python3 scripts/vk_setup.py --apply
```

Или переключитесь на обычные кнопки — в `config.toml`:

```toml
[policy]
use_callback_buttons = false
```

и `sudo systemctl restart massage-bot`. Пока не чините — подтверждайте командой
`/approve <номер>` (список: `/pending`).

## Мастеру не приходят заявки

ВКонтакте запрещает сообществу писать первым. Нужно один раз написать
сообществу **со страницы мастера** («привет»), затем:

```bash
python3 scripts/doctor.py --send-test
```

Также проверьте, что `ADMIN_VK_IDS` — это **числовой id**, а не `@имя` и не
`id123456` со словом `id`. Узнать: `python3 scripts/doctor.py --whoami`.

## Клиенту не приходят уведомления

- Он точно писал боту первым? Пока не писал — ВК не даст отправить сообщение
  (в логе будет предупреждение «нельзя писать peer …»).
- Проверьте очередь: `doctor` печатает «сообщений в очереди». Если число растёт
  и не падает — проблема с доступом к диалогу, смотрите лог.

## Нет свободных окон / клиенту не предлагается время

```bash
python3 scripts/doctor.py --slots
```

Типичные причины:

- `[schedule.hours]` пуст или день не входит в `work_days`;
- `min_notice_minutes` слишком большой (например 720 = 12 часов) — вечером окон
  на сегодня уже нет;
- всё занято заявками (`block_on_pending = true` держит слот даже за
  неподтверждённой заявкой; можно поставить `false`);
- стоят `/off` на ближайшие дни или `/block` на интервалы: проверьте
  `doctor` (печатает выходные и блокировки) и снимите `/on <дата>`,
  `/unblock <номер>`;
- `max_days_ahead` маленький — запись открывается только на 21 день вперёд.

## Время показывается не то (сдвиг на часы)

- `[bot] timezone` должен совпадать с городом мастера;
- системный часовой пояс: `timedatectl`;
- **менять timezone после того, как в базе появились записи, нельзя** — старые
  заявки останутся в прежнем времени. Если очень нужно: остановите бота,
  перенесите записи вручную или начните с чистой базы.

## Заявки «истекают» сами

Так работает защита: заявка без ответа мастера закрывается через
`pending_ttl_hours` (по умолчанию 24 ч), клиенту приходит вежливое сообщение.
Если вы отвечаете медленнее — увеличьте:

```toml
[reminders]
pending_ttl_hours = 72
```

## Напоминания не приходят

- Они создаются только для **подтверждённых** записей.
- Момент напоминания должен быть в будущем: если запись подтвердили за час до
  сеанса, напоминание «за 24 часа» уже не отправить (это нормально).
- Проверьте `[reminders] client_before_hours` — пустой список `[]` означает
  «не напоминать».
- Бот должен работать в момент напоминания. Если ноутбук был выключен,
  пропущенное напоминание не дублируется спамом: придёт одно, когда бот
  запустится.

## «Бот уже запущен»

Сработала защита от двойного запуска. Найдите процесс:

```bash
pgrep -af "bot.main"
systemctl status massage-bot
```

Оставьте что-то одно: либо службу, либо ручной запуск.

## База данных

```bash
python3 scripts/doctor.py            # печатает integrity_check и счётчики
./scripts/backup_db.sh               # копия (безопасно на работающем боте)
```

Файлы `massage.sqlite3-wal` и `-shm` рядом с базой — нормальны, не удаляйте их
при работающем боте.

Ошибка «database is locked» означает, что базу открыли два процесса (или вы
открыли её внешней программой). Закройте лишнее и перезапустите службу.

### Начать с чистой базы (сохранив старую)

```bash
sudo systemctl stop massage-bot
mv data/massage.sqlite3 data/massage-OLD.sqlite3
sudo systemctl start massage-bot      # создаст новую базу сам
```

## Спам / хулиганы в боте

- `cooldown_seconds` в `[policy]` гасит частые нажатия;
- `max_active_requests` ограничивает число заявок на человека;
- чтобы заблокировать человека совсем — добавьте его в чёрный список
  сообщества (Управление → Участники → Чёрный список); бот перестанет получать
  его сообщения.

## Как посмотреть, что бот делал ночью

```bash
journalctl -u massage-bot --since "03:00" --until "09:00" --no-pager
journalctl -u massage-bot -f                     # следить в реальном времени
```

Для подробного лога поставьте в `config.toml` `log_level = "DEBUG"` и
перезапустите службу. Потом верните `INFO` — DEBUG-лог растёт быстро.

## Куда писать, если не разобрались

Приложите к вопросу вывод трёх команд — этого обычно достаточно, чтобы понять
проблему:

```bash
python3 scripts/doctor.py --all
journalctl -u massage-bot -n 200 --no-pager
systemctl status massage-bot --no-pager
```
