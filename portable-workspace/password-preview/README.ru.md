# VIC-A — отдельный тест пароля и резервной фразы

**Это тест нового формата на искусственных данных. Импорта, запуска браузера, обновления подписки и удаления старых файлов здесь нет.** Рабочий vault V02 не читается и не меняется.

## Установка

1. Скачайте ZIP, в свойствах ZIP выберите «Разблокировать», если флажок есть, затем распакуйте в **`Z:\Iran\Browser\VIC-A-Password-Test`**.
2. В этой папке сразу должны лежать `Start-Test.cmd`, `Start-PasswordTest.ps1`, `PasswordEnvelope.cs`, `vault-preview` и остальные файлы комплекта.
3. Запустите **`Z:\Iran\Browser\VIC-A-Password-Test\Start-Test.cmd`**.

Требуются Windows PowerShell5.1 x64 и уже установленная проверенная криптобиблиотека в `VIC-A-Updated\vault-preview\lib`. При первом запуске копируются только `vica-sodium.dll` и `dependency.json` в **собственную папку теста** через проверенный stage; источник/версия/хеш и подписи зависимостей System32 проверяются как прежде. Ничего не скачивается, повышенные права не требуются.

## Что произойдёт

- Автоматическая самопроверка на искусственных паролях/данных: 17 проверок шифрования, повреждения, отказов, NFC, изменения/восстановления пароля. Если она не проходит, ввод пользовательского пароля не начинается.
- При первом создании задайте пароль и повторите его. Пароль не нужно генерировать из 10 слов: достаточно удобного **сильного пароля от8 до256 символов** (после NFC), минимум6 различных символов. Несколько несвязанных слов допустимы. Очевидные последовательности, повторения, полностью цифровой пароль, управляющие/format-символы и пробелы по краям не принимаются. Это эвристика, **не оценка энтропии и не полная база утечек**. Не используйте чужой/ранее засвеченный пароль.
- Программа отдельно сгенерирует **10 случайных резервных слов**. Сохраните их вне этого диска. Они будут видны в прокрутке консоли: не делайте скриншоты/транскрипты и не присылайте их в чат.
- Один раз повторите резервную фразу скрытым вводом: все10 слов, между словами один обычный пробел. Пароль и фраза должны открыть записанный stage до публикации тестового файла.
- Появится меню:
  1. открыть тест паролем;
  2. открыть тест резервной фразой;
  3. сменить пароль (нынешний пароль + резервная фраза);
  4. восстановить/сбросить пароль резервной фразой, без прежнего пароля;
  0. выйти.

Обычный вход в пункте1 требует **только пароль**, не резервные слова. После выхода/повторного запуска уже созданный тест открывается тем же паролем: заново задавать его не нужно. Пароль нигде открытым текстом не сохраняется.

При смене/сбросе пароля меняются случайный ключ данных и ID контейнера, а резервные слова остаются прежними. Для обычной смены требуется фраза, чтобы заново защитить новый ключ теми же словами без хранения самой фразы. При аварийном восстановлении достаточно фразы. Это редкая операция, не обычный вход.

## Что проверить

1. Пункт1 с правильным и затем заведомо неверным паролем.
2. Пункт2 с сохранёнными словами.
3. Закрыть тест и снова запустить: пароль не меняется, тестовый файл сохраняется.
4. Пункт4: слова → новый пароль дважды. Затем пункт1 принимает новый пароль, отвергает прежний; пункт2 всё ещё принимает ту же фразу.

В чат достаточно `создание OK / пароль OK / неверный пароль отклонён / фраза OK / восстановление OK`. Не присылайте пароль, слова или сами файлы.

## Файлы и безопасность

Все тестовые данные находятся только в **`VIC-A-Password-Test\test-data`**. `test.vault` содержит постоянную искусственную строку, а не вашу подписку. Изменения защищены эксклюзивной блокировкой, ограничением размера, записью stage + Flush(true), повторным открытием с диска и File.Replace с зашифрованным backup. Неизвестный существующий test-data без правильного маркера не перезаписывается. Ошибки учетных данных/политики не публикуют новый файл. Если сама операция файловой публикации дала сбой, сохраните тестовые backup для разбора.

**Слабый пароль делает украденный контейнер уязвимым к офлайн-перебору даже при сильной резервной фразе.** Каждый из двух способов независимо открывает ключ; ограничения попыток в интерфейсе не остановили бы офлайн-перебор, поэтому фиктивного «блокирования навсегда» нет.

Формат экспериментальный VICAPK03: случайный master-secret256бит, две независимые V02-обёртки (пароль/фраза) и V02-шифротекст данных. Каждая V02-обёртка использует прежние Argon2id13 ops3/64MiB + AES256GCM. Ключ данных выводится из случайного master-secret через ту же функцию, без самодельного шифра. Роли и случайный ID связаны аутентификацией; данные дополнительно связывают хеши обеих обёрток, поэтому повреждение даже неиспользуемой recovery-обёртки не проходит незамеченным при входе паролем. См. FORMAT.md.

10 слов получаются из прежнего проверенного генератора EFF7776: два независимых набора по6 слов, используются первые10 из12. Распределение остаётся равномерным, повторы допустимы, приблизительно129.25бит при сохранении случайного выбора. Пароль пользователя такой гарантии не имеет.

Старые зашифрованные backup принимают свои старые пароли и содержат старые данные. В новом текущем контейнере после смены пароля используется новый master-secret: одного старого backup+старого пароля недостаточно для нового контейнера. Знание неизменённой резервной фразы по-прежнему открывает обе версии — это её назначение. Защита от подмены всей старой версией (rollback) не реализована.

Управляемые строки .NET/PowerShell, прокрутка консоли, pagefile/crash dumps не поддаются гарантированному стиранию. SecureString не защищает от заражённого/привилегированного хоста. Безопасное удаление с SSD и гарантии при потере питания не обещаются.

## Дальнейший импорт — только после проверки

Рабочие папки **не удаляем**. После успешного теста отдельно подготовим импорт нужных данных в новый контейнер с **новым случайным ключом**, не перенося тестовый master-secret в продуктивную версию. Пароль/резервные слова можно будет сохранить, но для защиты нового ключа при импорте потребуется ввести их локально. Затем проверим запуск/подписку и только после этого составим точный список удаления. Никакой автоматической уборки в этом комплекте нет.

## Проверки здесь

Реальное исполнение нового C# с официальной libsodium1.0.22 на Linux и независимое открытие через argon2-cffi/cryptography; компиляция C#5, тесты повреждений/смешения слотов/ротации ключа/NFC. Это не запуск PowerShell5.1/Win32; встроенная самопроверка предназначена для проверки криптопути и .NETFramework на вашем Windows. Это не обещание отсутствия любых уязвимостей или независимый аудит.

Minimum-password update: test-only packaged Crypto.Seal minimum is8 (production source unchanged). Argon2id/AES-GCM and the envelope format are unchanged. Eight characters permit substantially easier offline guessing; prefer a longer random password.
