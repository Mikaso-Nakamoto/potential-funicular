# VIC-A — повторное ревью после замечаний эксперта

## Назначение архива

Это исходники для аудита, НЕ инструкция миграции и НЕ утверждение о безопасности.
В архиве полный текущий tracked-каталог portable-workspace: основа шифрования,
установщик, тесты, спецификация и существующие launch/update/menu/install скрипты
для контекста. Некоторые старые документы описывают более ранние этапы; статус
текущего ревью указан здесь. Реальных Runtime, профиля, подписки, HWID, пароля,
загруженных DLL и локальных dependency.json в архиве нет. Синтетический пароль
в tests/synthetic-vector.json публичный, намеренно не секретный.

review/changes-since-expert.patch — изменения portable-workspace от 6950294
(снимок до исправлений) до b6bad537000c3bf6593a8237e7a57f94b0695ef1.
review/COMMITS.txt — история этих изменений. SHA256SUMS.txt — хеши содержимого
архива для сверки, не независимая криптографическая подпись автора.

## Что изменено по замечаниям

1. Политика пароля: минимальная длина после NFC, отклонение некоторых общих
   шаблонов, периодических повторов и малого числа различных символов.
   Это НЕ zxcvbn, НЕ измерение энтропии и НЕ доказательство стойкости.
   Рекомендуются 6 независимо случайных слов, полученных в доверенном менеджере.
   Встроенного генератора фраз/словаря пока нет; пункт стойкости остаётся предметом ревью.
2. NFC перед строгим UTF-8; новый magic VICAVA02. VICAVA01 отвергается.
   KDF прежний: Argon2id13, ops=3, 64 MiB, p=1 в libsodium; не профиль p=4 RFC 9106.
   Политика версионирования описана в FORMAT.md.
3. Абсолютный путь основной DLL плюс DefaultDllImportSearchPaths с
   UseDllDirectoryForDependencies | System32. Ошибочное имя DllLoadDir было
   обнаружено Windows-компиляцией и исправлено во всех семи атрибутах.
4. SHA-256 C# закреплён в Vault.Common.ps1. Это обнаружение отдельного изменения,
   а не защита от одновременной подмены исходника и проверяющего скрипта.
5. Проверка объекта activeConfig выделена из существующей проверки файла:
   Assert-ConfigObjectPolicy. Assert-VaultDocument вызывается при чтении/записи.
   Assert-ConfigPolicy остаётся совместимой файловой обёрткой; правила не ослаблялись.
6. CreateNew staging, Flush(true), закрытие, аутентифицированное read-back,
   публикация File.Move без замены. Обновления существующего vault пока нет.
7. Вместо распаковки MinGW tar: закреплённый официальный MSVC ZIP; выбирается
   только один x64/Release/v143/dynamic/libsodium.dll. Проверяются имена записей,
   тип и размер выбранного member; читается только он и пишется в фиксированный
   staging-файл. Архивные пути не используются как выходные пути распаковки.
8. Vault читается через один открытый FileStream с ограничением размера и
   точным чтением, без отдельной Get-Item/ReadAllBytes пары для vault.

## Зависимости — важная история и результат

Первый пользовательский Windows-запуск правильно отверг официальную MinGW DLL:
она импортирует libgcc_s_seh-1.dll. Этот импорт в allowlist не добавлялся.

Теперь официальный libsodium-1.0.22-msvc.zip из jedisct1/libsodium, тег
1.0.22-RELEASE; SHA-256:
3e03a726fac4bc09cb61d8f29d658ef7a5eca0811de59082130414f7ca2e4279.

MSVC ReleaseDLL использует внешний Microsoft CRT. Проверяются необходимые
vcruntime140.dll/vcruntime140_1.dll только из System32: наличие, reparse flag,
Valid Authenticode и O=Microsoft Corporation; затем анализируются и их импорты.
Узко разрешены некоторые Windows-модули и UCRT API contracts. Это не полный
рекурсивный аудит ОС, не анализ динамических GetProcAddress/forwarded exports
и не защита от заранее загруженных злоумышленником модулей во враждебном процессе.
Обязательное условие переносимости — подходящий Microsoft VC++ x64 runtime на ПК.
Его установщик здесь не скачивается и не запускается. Проверяется runtime version
libsodium 1.0.22. Не обещается независимость от всех системных компонентов Windows.

## Что действительно проверено

В среде разработки: 8 Linux Python-тестов формата с libsodium из PyNaCl и
независимой сверкой argon2-cffi/cryptography; статический tree-sitter разбор.
Статический разбор НЕ обнаружил неправильное имя enum, поэтому не заменяет компиляцию.

Пользователь предоставил скриншот успешного Windows-запуска ПОСЛЕ compile-fix,
в Windows PowerShell 5.1, x64 (предыдущий отчёт показывал 5.1.26100.10068).
Видны финальный PASS и успешное завершение следующих наборов:
- synthetic PE inspector;
- фактические PE-импорты MSVC libsodium и Valid Microsoft signature vcruntime140.dll;
- C# compile/load, libsodium runtime 1.0.22, crypto interoperability/round-trip,
  password/tamper/truncation; NFC и слабые шаблоны входят в завершившийся Test-Vault;
- создание/flush/read-back, отказ от перезаписи, wrong password, locked file,
  confirmation mismatch, missing parent, policy rejection на записи и чтении,
  oversize/short stream, сохранность baseline и отсутствие staging после тестов;
- отдельные процессы отклонили изменённые DLL/manifest/C# на нужных integrity gates.

Это сообщение результата по скриншоту пользователя, НЕ независимый запуск эксперта.
Полный файл успешного vault-test-report.txt и сама фактическая DLL в среду агента
не передавались и в этом архиве отсутствуют. Не выдавать этот текст за исходный лог.
Скрипты тестов и инструкции для воспроизведения включены полностью.

## Что ещё НЕ готово и не защищено

Start-Workspace.ps1 и Update-Subscription.ps1 всё ещё используют открытый
private/xray.json. Пароль для реального подключения/обновления НЕ обеспечивается.
Меню не интегрировано. В payload нет списка узлов/идентичности выбранного узла.
Prepare-Vault создаёт только зашифрованную копию и оставляет оригинал; реальный
пользовательский Create/Check по представленному скриншоту не подтверждён.

Не выполнены: Xray stdin lifecycle/error isolation, безопасное обновление vault,
восстановление после аварии, disk-full/power loss/unplug, adversarial ZIP suite,
отдельная машина без AES/без VC runtime, полноценный файл-системный race/reparse
аудит. Часть ошибок обобщена; диагностику и ограничения схемы JSON стоит проверить.
Тест invalid parent не эквивалентен симуляции диска, заполненного посреди записи.
Flush(true)+Move не гарантируют сохранность при всех отказах носителя/питания.

## Особое внимание при повторном ревью

- Крипто-формат, точность спецификации относительно кода, NFC/Unicode edge cases,
  границы пароля, эвристики и обоснование параметров KDF.
- ABI, .NET/PS5.1 совместимость, действительный порядок поиска/предзагрузка DLL,
  сертификаты/runtime gate, локальный manifest, чтение исходника после hash check.
- Парсер PE: bounds/RVA/import table/delay imports, достаточность allowlist.
- ZIP: canonical names, duplicate members, attributes, размер/чтение,
  доверие к закреплённому хешу GitHub и обработка неизвестного layout.
- TOCTOU при других чтениях помимо vault, reparse points, кооперативные блокировки,
  владение staging и cleanup, аварийная устойчивость и будущий протокол замены.
- Полная валидация schema/config, неожиданные JSON типы/дубликаты/глубина/ресурсы.
- Managed strings/GC/BSTR: очистка памяти лишь best effort. Строки JSON/URL/NFC
  могут оставаться; malware/admin/pagefile/hiberfil/rollback не устранены.

Старые plaintext-копии на SSD не могут быть гарантированно стёрты программным
удалением. Браузерный профиль/cookies/downloads не шифруются этой функцией.
Просьба выдать findings с severity, сценарием воспроизведения и границами модели
угроз. Автоматическое удаление исходных открытых конфигов до миграционных тестов
не планируется. Текущие тесты не являются заключением независимого аудита.
