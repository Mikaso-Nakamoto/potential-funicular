# VIC-A: экспериментальная основа зашифрованного хранилища

**Не готовое обновление защиты. Не заменяет текущую установку.**

Этот каталог изолирован от рабочего меню: `Start-Workspace.ps1` и
`Update-Subscription.ps1` пока не используют хранилище, пароль для подключения
и обновления **не требуется**. Архивы в `downloads/` не обновлены.
Не удаляйте рабочий `private\xray.json` и не считайте его защищённым после создания копии.

## Исправления после экспертного ревью

Точная спецификация нового экспериментального формата — `FORMAT.md`.
Magic теперь `VICAVA02`; `VICAVA01` не открывается автоматически.
Добавлены NFC, эвристическое отклонение слабых паролей (не оценка энтропии),
ограничение поиска зависимостей DLL каталогом DLL и System32, закреплённый хеш C#,
проверка объекта activeConfig без открытого файла, ограниченное чтение через один
FileStream, CreateNew и Flush(true) перед публикацией.
Установщик извлекает только один проверенный regular-file member, а не весь архив.

**Ещё не закрыто:** фактический анализ импортов Windows DLL и выполнение Windows
негативных тестов загрузчика/архива/записи. Не переходить к миграции.
Ранее опубликованный текст Expert-Review — исторический снимок до этих исправлений.

## Что сделано

- Обёртка над официальной libsodium: AES-256-GCM, Argon2id13 (3 прохода,
  64 МиБ, параллелизм 1). Никакой собственной реализации шифра.
- Новый случайный salt 16 байт и nonce 12 байт при каждом шифровании.
  Заголовок аутентифицирован. Ограничение открытых данных — 8 МиБ.
- Переносимость без DPAPI/привязки к Windows-пользователю. Требуются Windows x64,
  64-битный PowerShell 5.1 и поддерживаемое AES-GCM аппаратное ускорение.
  Без ускорения операция прекращается; слабого резервного режима нет.
- Пароль от 16 символов при создании; пароль и ключ не сохраняются.
- Создание только нового `Runtime\private\workspace.vault`, проверка повторным
  паролем и чтением записанного шифротекста до публикации. Перезапись запрещена.
- В копии пока только URL, существующий HWID и текущий конфиг — **не список
  серверов и не полноценное состояние обновления**.
- Отдельный тест на вымышленных публичных данных, не читающий Runtime.

## Что проверено здесь

В Linux выполнены 8 Python-тестов (включая NFC/NFD и отказ от старого magic): совместимость формата libsodium,
независимая сверка с argon2-cffi и cryptography, неверный пароль,
изменение заголовка/шифротекста/тега, усечение, изменение salt/nonce.
В `tests/synthetic-vector.json` — исключительно публичные вымышленные данные;
фиксированные salt/nonce допустимы **только для теста**.

PowerShell/C# проверяются статическим синтаксическим разбором. Это не компиляция
C#, не запуск Windows и не аудит безопасности. Установка DLL, P/Invoke,
`Test-Vault.ps1`, создание/проверка копии на Windows ещё не выполнены здесь.
Успешные Python-тесты не доказывают работоспособность Windows-обёртки.

## Порядок будущей проверки на Windows

Это описание для разработчика, не рекомендация обновлять рабочую установку сейчас.
После ревью скриптов: установить зависимость через `Install-VaultDependency.ps1`,
запустить `Test-Vault.ps1` в новом 64-битном PowerShell. Только после успешного
теста обсуждать запуск `Prepare-Vault.ps1 -Action Create` и затем `-Action Check`
в другом процессе с Root `Z:\Iran\Browser\Runtime`.
Create запрашивает скрытые URL/HWID и новый пароль дважды; Check не показывает секреты.
Оригиналы не удаляются. Не передавайте пароль аргументом командной строки.

Зависимость скачивается только из официального релиза jedisct1/libsodium 1.0.22,
архив закреплён SHA-256. Хеш из GitHub не является независимой подписью.
Хеш DLL в локальном manifest обнаруживает случайные изменения, но не защищает
от атакующего, способного переписать manifest/скрипты. Лицензия библиотеки —
`LICENSE.libsodium.txt`. Двоичные зависимости и staging не включаются в Git.

## Что ещё обязательно до выпуска

1. Проверить C#/P/Invoke и все сценарии на Windows 5.1, включая отсутствие AES,
   неверный пароль, недоступный/повреждённый DLL и прерывание записи.
2. Передавать конфиг Xray через stdin без постоянного открытого файла,
   ограничить время/вывод дочернего процесса, не выводить его секретный stderr.
3. Перевести запуск на обязательную разблокировку без отката к plaintext.
4. Сохранить список узлов и идентичность выбранного узла внутри vault;
   отдельная кнопка обновления с сохранёнными URL/HWID. Не менять узел молча,
   если он исчез. Публиковать только полностью проверенное новое состояние.
5. Отдельный выбор сервера и изменение меню; тесты ошибок сети, блокировок,
   неверного пароля, сохранности предыдущего рабочего состояния.
6. Явная миграция после проверки пользователем; никакого автоматического
   удаления старого рабочего конфига до проверки нового пути.

## Ограничения

Забытый пароль восстановить нельзя. Нужна длинная уникальная парольная фраза.
Браузерный профиль, cookies и загрузки этим хранилищем не шифруются.
Секреты доступны работающему процессу; malware/admin/дампы/подмена скриптов
не входят в защиту. В .NET/PowerShell нет гарантии очистки всех копий строк
из памяти; очистка байтовых буферов — лишь best effort. Старые открытые копии
на SSD нельзя гарантированно стереть программным удалением.
