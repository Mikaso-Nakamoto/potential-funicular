# Повторные исправления R3 — начать ревью здесь

Архив содержит полный текущий portable-workspace для контекста, а не только патч.
Старые документы/EXPERT-HANDOFF описывают прошлые этапы; текущая спецификация —
vault-preview/FORMAT.md, инструкции тестов — TEST-KIT.ru.md, этот файл — статус R3.
Не запускать миграцию. Обязательное шифрование подключения/обновления НЕ интегрировано.

## Изменения после второго заключения

1. Удалена эвристика стойкости как способ допуска к созданию. Создание через
   Write-NewVault принимает только токен встроенного генератора, а Prepare-Vault
   генерирует шесть слов и требует повторного ввода. Словарь EFF large: 7776 слов,
   неизменённые bytes, хеш в C#, атрибуция CC BY 3.0 и pinned mirror commit в words/NOTICE.
   Выбор — libsodium randombytes_uniform, с возвращением, без фильтрации результатов.
   Равномерная генерация даёт около 77.55 бита; это НЕ оценка произвольной строки.
   Crypto.Seal остаётся низкоуровневым API для тестов/совместимости. Произвольный
   доверенный код может обойти workflow; защита не рассчитана на замену скриптов.
2. Удалён UseDllDirectoryForDependencies со ВСЕХ P/Invoke. Только System32 для
   зависимостей, основная библиотека по абсолютному пути. Новый Windows-тест кладёт
   неисполняемые invalid-image canary DLL рядом с sodium в отдельной полной копии,
   проверяет инициализацию и фактические пути загруженных VC runtime. Если runtime
   был предзагружен, это отмечается как ограничение проверки first-load.
3. Закреплены хеши SodiumPe.cs и Test-SodiumImports.ps1 в Common; gate проверяет
   хеш тех самых байтов SodiumPe, которые компилирует. Установщик проверяет support
   pins до загрузки. Хеши НЕ заменяют подпись и не защищают от переписывания verifier.
4. Мутации DLL/manifest/C#/gate/PE выполняются в полных копиях с нужными helper,
   word list и fixtures. Чистая полная копия сначала должна пройти crypto и I/O.
   Reports содержат SHA-256 входов, версии PS/CLR/OS, явные ограничения тестов.
5. Надёжность записи НЕ выдана за решённую: Flush(true) недостаточен для полной
   crash durability; нет fsync каталога/write-through/восстановления после сбоя.
   Ни исходные конфиги, ни старый vault не удаляются автоматически.

## Результаты R3 и происхождение подтверждения

В Linux прошли 12 Python-проверок, статический разбор 14 C#/PS файлов.
Это не Windows execution. Однако ПОСЛЕ коммита R3 пользователь передал оба полных
Windows-отчёта: evidence/r3-windows-user/vault-install-report.txt и vault-test-report.txt.
Они теперь приложены без изменения исходных байтов; provenance/границы — README.md
в том же каталоге. Проверенный код: 19fb07f18686d96e47252432869a69eccedc6431.
19 хешей source/fixture/list из отчёта совпали с файлами этой версии и текущими
исполняемыми файлами. DLL/локальный manifest здесь отсутствуют, их байты не сверялись.

По отчётам все реализованные R3-наборы завершились PASS: Windows PowerShell 5.1
x64, генератор, crypto/NFC, I/O/policy, full-copy baseline, пять мутаций и canary.
Canary сообщил, что VC runtime не был предзагружен; затем найден System32\VCRUNTIME140.dll.
Это пользовательский процесс-локальный regression result, НЕ независимый аудит
и не доказательство поведения на всех машинах/во всех состояниях загрузчика.

R2-скриншот не используется вместо этого R3-протокола. На чистой Windows/другом CPU
здесь ничего не запускалось. Приложенные отчёты не подписаны и не защищены от
подделки; хеши связывают заявленные входы с кодом, но не доказывают подлинность исполнения.
В ZIP нет реальных subscription/HWID/password, Runtime/profile, скачанных DLL
или локальных dependency.json. Есть только пользовательские синтетические тестовые отчёты.
Открытые xray.json/browser profile ещё остаются обходом, не покрываемым прототипом.
Зависимости скачиваются только из закреплённого официального MSVC-релиза;
без Microsoft VC runtime в System32 проверка остановится, ничего не устанавливая.
Потерянный пароль невосстановим. Managed strings/scrollback/GC/pagefile/host malware,
rollback, подмена всей поставки и power loss не объявляются устранёнными.
