# VIC-A: исправление осиротевшего Xray и исчезающих ошибок

## Что это и что НЕ обещаем
Это отдельный кандидат исправления запуска, НЕ завершение всего продукта. В этой среде
новый C#/Win32 helper не компилировался и не выполнялся на Windows. Статический разбор
и source-contract тесты не заменяют реальный запуск. Поэтому Start.cmd сначала проверяет
ровно заявленное исправление на собственных процессах, не на пользовательском Runtime:
обычный stop job дерева и принудительное завершение supervisor без managed finally.
Если проверка не прошла, к рабочему Runtime меню не переходит. При каждом запуске
кандидата проверка повторяется; сохранённый отчёт job-lifecycle-report.txt.

## Установка без частичного обновления рабочей программы
Распаковать ZIP в НОВЫЙ Z:\Iran\Browser\VIC-A-Launcher-Repair.
Не копировать отдельные PS1 поверх рабочего корня. Исходные launcher и Runtime остаются.
Обычный Windows PowerShell 5.1 x64 / обычные права, не admin/Bypass. Закрыть текущую
сессию обычным способом до проверки. Если 17890 занят старым Xray, новый launcher его
НЕ убивает/не присваивает. Не удалять lock и не отключать защиту при ошибке.
Запуск: VIC-A-Launcher-Repair\Start.cmd. После self-check откроется знакомое меню.
Рабочий Runtime берётся из соседней папки ..\Runtime, не из vault-preview.
Проверки используют только owned .job-test-GUID рядом с пакетом, без сети/порта/browser.
JobFixture.exe компилируется из synthetic C# и удаляется только при проверенном отсутствии
процессов из stage. При ошибке stage может сохраниться. Защиту ради fixture не отключать.

## Исправление
- Xray run И native -test создаются через CreateProcessW с CREATE_SUSPENDED|CREATE_NO_WINDOW.
- Приватный unnamed Job Object с KILL_ON_JOB_CLOSE создаётся заранее; не наследуется.
- AssignProcessToJobObject должен успешно выполниться ДО ResumeThread. Никакого запуска
  без Job при несовместимом окружении; ошибка видна пользователю.
- При закрытии/убийстве процесса-владельца Windows закрывает его job handle и завершает
  связанные процессы. Потомки наследуют job, breakaway не разрешён. Это не Job браузера:
  LibreWolf запускается отдельно, возможные несохранённые данные не убиваются этой логикой.
- Штатный stop вызывает TerminateJobObject и QueryInformationJobObject: ждёт activeProcesses=0.
  Если не подтверждено, job handle и session lock удерживаются, выполняются повторные попытки.
- Browser launch attempt отслеживается до Start-Process: ошибка возврата handle не объявляет
  профиль свободным автоматически. Мониторинг browser/profile остаётся консервативным.
- Ошибка запуска показывается с фиксированным именем этапа в окне с ожиданием Enter,
  вместо мгновенного закрытия. Секретные config/native diagnostics не выводятся.
- TEMP/TMP helper compilation задаются в Runtime/private/tmp ДО native validation.

## Что не исправлено этим пакетом
Старый осиротевший PID не позволяет установить историческую причину его появления.
Проверяется устранение путей orphan при новом запуске, а не реконструкция старого события.
Не обещается корректное восстановление после power-loss/OS failure/hostile host.
Сбой OS API создания/назначения/уничтожения процесса до передачи ownership остаётся
исключительной веткой: suspended child не получает возможность выполнять Xray до assign;
при startup error предпринимается TerminateProcess, без uncontained fallback.
Nested job restrictions могут запретить запуск на части хостов; понижать изоляцию не будем.
Не закрывайте supervisor намеренно при несохранённой работе: браузер останется без туннеля.
Job — containment Xray, не системный kill switch и не изоляция локального SOCKS от других apps.

Подписка/INCY/curl/туннельный refresh этим исправлением НЕ доведены. Пункт 3 старого меню
остаётся прежним plaintext updater, не использовать для экспериментов с рабочим vault.
Vault-only launcher не переключён на новый Job helper: это отдельный дальнейший перенос,
старые пакеты сами не обновляются. Не путать починку legacy запуска с защищённой миграцией.
Оригинальные Runtime/private/xray.json, browser profile, downloads и vault не удаляются,
не копируются и не мигрируются установкой пакета. При обычном запуске профиль обрабатывается
ровно существующим launcher: обновляются proxy prefs, как раньше; профиль не зашифрован.

## Приёмка после self-check
1. Пункт 1 открывает настоящий браузер, порт принадлежит Xray этой сессии.
2. Штатное закрытие браузера завершает session window, 17890 свободен.
3. До использования кандидата постоянно нужен Windows отчёт self-check и результат normal
   real browser session. Не называть это уже проверенной на Windows программой заранее.
Общий hash архивов не является цифровой подписью. Код и helper pins считаются доверенными.
