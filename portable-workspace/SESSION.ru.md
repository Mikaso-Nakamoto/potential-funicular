# Следующий этап: подписка и управляемый сеанс

**Статус: экспериментальная версия для повторного аудита и домашней проверки, не готовый комплект для общего ПК.** См. AUDIT.ru.md.

## Куда положить

Рядом с уже установленным `Runtime` скопируйте **все три** файла:

```text
Z:\Iran\Browser\
  Workspace.Common.ps1
  Update-Subscription.ps1
  Start-Workspace.ps1
  Runtime\
    LibreWolf\
    Xray\
    install-manifest.json
```

Установщик повторно запускать не надо. Вспомогательные файлы не скачивают браузер/ядро повторно.

## 1. Получить подписку и выбрать узел

На собственном доверенном Windows-ПК, обычный PowerShell 5.1 без администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File "Z:\Iran\Browser\Update-Subscription.ps1"
```

Полный HTTPS URL вводится в скрытом приглашении, а не аргументом команды (чтобы не попадать в историю команд). URL не сохраняется. Запрос использует `User-Agent: v2rayNG`, Accept text/plain, системное доверие TLS и текущую сеть Windows. **Это первоначальное прямое получение подписки, не запрос через будущий Xray**. Системный прокси также может влиять на этот запрос. Редиректы намеренно запрещены; если провайдер их использует, сначала выясните официальный конечный HTTPS адрес. Не отключайте проверку сертификатов.

Поддержаны plain text / Base64 (включая URL-safe) списки. Base64 не шифрование. HTML/JSON/YAML и неизвестные схемы не поддерживаются. Из смешанного списка выбираются только поддерживаемые VLESS; число пропущенных записей и сгруппированные фиксированные причины отказов показываются. Неизвестные имена параметров и тексты исключений .NET не печатаются. Выбор узла явный, по номеру в порядке подписки; названия и адреса не выводятся, чтобы не раскрывать приватные данные и не печатать управляющие последовательности из ответа.

Поддержка: VLESS с UUID, encryption=none; TCP/RAW + TLS или REALITY; WS + TLS; flow пустой либо xtls-rprx-vision для TCP. REALITY использует поле Xray `password`, заполняемое из URI `pbk`; WebSocket использует `wsSettings.host`. Оба поля сверены с исходниками Xray v26.11.9. `headerType=none` разрешён только для TCP/RAW. XHTTP, gRPC, HTTPUpgrade, расширенное VLESS-шифрование и неизвестные query-параметры отклоняются, а не отбрасываются молча. Расширять поддержку нужно по реальному формату провайдера. Не присылайте полные ссылки: для диагностики достаточно названий параметров и обезличенных type/security/flow.

`xray run -test` проверяет синтаксис/поддержку конфигурации, **не работоспособность удалённого узла**. Существующий `private\xray.json` заменяется только после успешной проверки. Если первая конфигурация отсутствует, файл создаётся перемещением; существующая заменяется File.Replace без delete-then-move. На неподдерживаемой файловой системе обновление остановится; рекомендуется NTFS. Файлы кандидата и активной конфигурации содержат секреты в открытом виде. URL не хранится, но UUID/параметры выбранного узла — хранятся. Автоматического периодического обновления пока нет: повторяйте команду вручную при закрытом управляемом сеансе.

## 2. Запустить

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File "Z:\Iran\Browser\Start-Workspace.ps1"
```

Скрипт проверяет конфигурацию, свободный порт, запускает только свой Xray и проверяет владельца SOCKS listener на 127.0.0.1:17890. Затем открывает именно `librewolf.exe` с отдельным `private\profile` через `-wait-for-browser -no-remote -new-instance -profile`. Штатный portable launcher/updater не используется. Обычные профили Windows не импортируются. user.js выделенного профиля записывается при каждом запуске. Не используйте эту папку для чужого профиля или ручного запуска.

Прокси SOCKS5 с удалённым DNS, пустым списком исключений и отключённым прямым fallback. WebRTC и HTTP/3 отключены, DNS prefetch/DoH отключены. В Xray нет freedom/direct outbound: только выбранный VLESS. Локальное разрешение имени самого VLESS-сервера может потребоваться Xray для первоначального соединения — это не DNS-запросы посещаемых браузером сайтов.

**Не закрывайте окно PowerShell во время работы.** После падения Xray скрипт предупреждает и продолжает ждать браузер, сохраняя lock. Завершение проверяется по launcher-процессу, занятости parent.lock и процессам librewolf.exe из этого каталога (включая дочерние); затем останавливается свой Xray и ожидается его завершение. При невозможности определить путь процесса LibreWolf ожидание консервативно продолжается — это может удерживать lock даже из-за постороннего LibreWolf. При ошибке CIM мониторинг также удерживает lock, а не объявляет профиль свободным. Это не эквивалент Windows Job Object и не доказательство управления любыми будущими дочерними процессами.

При принудительном завершении PowerShell `finally` может не выполниться: Xray может остаться с открытым SOCKS-портом. Автоматическое завершение по закрытию родительского процесса через Job Object **пока не реализовано**. Не используйте эту версию на общем ПК как готовое решение. После аварии проверьте процессы вручную по пути/командной строке, не завершайте все процессы по одному имени. Обновление дополнительно отклоняется, пока parent.lock профиля занят.

Для дочерних процессов TEMP/TMP направлены в `Runtime\private\tmp`, обычная папка загрузок — `Runtime\private\downloads`; исходные переменные окружения PowerShell восстанавливаются. Это только настройки путей: не все компоненты обязаны им следовать. Временная папка автоматически не стирается, как и cookies/история/сессии постоянного профиля. Проверьте путь загрузок и фактические настройки в браузере.

Обновление подписки и управляемый сеанс используют общий файловый lock: два таких скрипта одновременно не работают. Ручной запуск программ за пределами скриптов этим не блокируется.

## 3. Проверить до входа в аккаунты

1. Откройте `about:config`: проверьте network.proxy.type=1, SOCKS 127.0.0.1:17890, SOCKS5 и remote DNS. Настройки/политики LibreWolf и расширения могут влиять на фактическое поведение.
2. В браузере проверьте внешний IP и DNS на доверенном проверочном сайте: должны соответствовать выбранному туннелю, не обычному подключению. Проверочные сайты сами получают ваш IP.
3. Найдите **именно этот** xray.exe в диспетчере задач по пути и командной строке, завершите его, затем попробуйте открыть новый, ранее не посещённый HTTPS сайт. Запрос должен завершиться ошибкой, а не пройти напрямую. Кешированная страница/Service Worker не доказывает сетевой доступ. Это тест, после него запустите сеанс заново.
4. Проверьте закрытие: закройте браузер нормально, убедитесь, что запущенный скриптом Xray завершился, и только затем безопасно извлеките SSD.

Пока эти проверки не пройдены, не используйте профиль для чувствительных аккаунтов. Это **настройка браузерного прокси, не системный firewall kill switch** и не защита от злонамеренного локального ПО. Другие программы, скачанные документы и внешние обработчики могут обращаться в сеть напрямую. SOCKS не аутентифицирован: другие локальные процессы могут использовать его во время сеанса. От администратора/EDR на компьютере профиль и ключи не скрыты. Туннель не скрывает сам факт подключения к серверу.

## Данные и ограничения

`Runtime\private` содержит профиль с сессиями и конфигурацию с UUID. Не добавляйте эту папку в Git, облачную синхронизацию или сообщения. Для потери/кражи SSD нужна отдельная защита шифрованием; переносимость DPAPI между ПК не предполагается. Скрытый ввод URL не гарантирует стирания строк из памяти, буфера обмена, pagefile или системных журналов. Автоматической очистки и безопасного стирания нет. Скрипты не чистят журналы Windows.

Новая логика подготовлена в Linux; Windows-процессы, Get-NetTCPConnection, сетевой запрос к вашей подписке и интеграция с LibreWolf здесь не испытывались. Сначала тестируйте на домашнем ПК. Если скачанные .ps1 заблокированы Windows, после просмотра исходников снимите блокировку файлов, не обходя политики организации.

## Дополнительные проверки этой редакции

- Размер HTTP-ответа теперь ограничен при чтении потока: максимум 4 194 304 байта после распаковки HTTP; память не принимает весь произвольно большой ответ. Внутренние сетевые буферы также существуют. Ответ декодируется из UTF-8 байтов, включая application/octet-stream.
- HTTP-таймаут 45 секунд на получение ответа, read timeout 15 секунд; дополнительно проверяется время чтения потока. Это не строгий общий deadline всей операции.
- Проверка Xray через ProcessStartInfo читает stdout/stderr параллельно и подавляет диагностику, с ожиданием до 30 секунд.
- Автоматические обновления безопасности не отключаются. Несуществующий socks5_remote_dns удалён; captive portal/connectivity probes отключены. IPv6 глобально не отключается: это не замена контролю фактических сетевых соединений.
- Lock освобождается вложенным finally даже при ошибке удаления кандидата. File.Replace по-прежнему без опасного fallback.
- Корень для этой установки — **Z:\Iran\Browser\Runtime**. Дефолт верен при размещении скриптов рядом с Runtime. Не используйте `-Root Z:\Iran\Browser`, если в нём нет непосредственно каталогов Xray и LibreWolf.
