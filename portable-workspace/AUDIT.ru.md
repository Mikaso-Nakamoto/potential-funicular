# Разбор внешнего аудита — 2026-11-22

Статус: исправления подготовлены для повторной проверки. Ни успешный синтаксический разбор, ни `xray run -test` не подтверждают отсутствие утечек или работоспособность удалённого узла. Windows-интеграционные тесты здесь не выполнялись. Реальную подписку не запрашивали.

## Замечания о схеме Xray

Сверено с официальными исходниками тега **v26.11.9** (не с произвольной старой документацией):

- [transport_security.go](https://github.com/XTLS/Xray-core/blob/v26.11.9/infra/conf/transport_security.go): REALITYConfig содержит и Password `json:"password"`, и PublicKey `json:"publicKey"`. Build при непустом Password присваивает его PublicKey, затем проверяет полученный X25519-ключ. Поэтому `password = pbk` здесь допустимо; утверждение, что оно обязательно неверно, не подтверждается. Поле оставлено без изменения, оба одновременно не добавляются.
- [transport_method.go](https://github.com/XTLS/Xray-core/blob/v26.11.9/infra/conf/transport_method.go): WebSocketConfig содержит Host `json:"host"`; Build использует его напрямую. Host в Headers вызывает предупреждение об устаревании и переносится в Host. Поэтому замена wsSettings.host на headers.Host не требуется.

Это проверка конкретного тега. Фактическую установленную версию посмотрите в install-manifest.json; новые релизы могут менять схему. `Test-Parser.ps1` проверяет только построение объектов, не валидность синтетического REALITY-ключа и не сетевое соединение.

## Внесено

1. Native stderr больше не проходит через PowerShell `2>&1`. ProcessStartInfo перенаправляет оба потока, читает их асинхронно и не печатает; ожидание теста ограничено 30 секундами, диагностика подавляется и при исключении.
2. HTTP-ответ читается потоком с проверкой размера до записи следующего блока в MemoryStream. Максимум 4 МиБ распакованных данных. Обрабатывается UTF-8 из байтов независимо от Content-Type. Редиректы запрещены.
3. Открытый смешанный список распознаётся по URI-схеме любой строки, не только по vless в начале всего ответа. Неподдерживаемые элементы всё равно пропускаются.
4. Разрешён headerType=none только для TCP/RAW. Другие headerType отклоняются. Причины отказов группируются; только известные фиксированные сообщения попадают на экран, не произвольный текст исключения, имя параметра или содержимое ссылки.
5. Dispose lock гарантирован вложенным finally, SecureString освобождается. Это **не** гарантия зануления всех строк/копий в памяти .NET. ZeroFreeBSTR очищает только выделенный BSTR.
6. При смерти Xray скрипт предупреждает и ждёт браузер, удерживая lock. Добавлен -wait-for-browser, проверка parent.lock и консервативная проверка процессов LibreWolf, а также ожидание завершения своего Xray перед снятием lock. При ошибке инспекции ожидание не объявляет профиль свободным.
7. TEMP/TMP для дочерних процессов и стандартные загрузки направлены на SSD. $profile переименован в $profileDir. Удалён socks5_remote_dns, отключены captive portal/connectivity probes. Автообновления безопасности не отключаются.
8. Уточнён путь: установленный комплект находится в Z:\Iran\Browser\Runtime. Дефолт скриптов при их размещении в Z:\Iran\Browser верен. Команда из аудита с -Root Z:\Iran\Browser для этой структуры неверна.

## Пока не решено / не обещается

- SOCKS без аутентификации на 127.0.0.1:17890 доступен другим локальным процессам и пользователям. Случайный порт сам по себе это не исправляет; надёжная SOCKS-аутентификация через штатные prefs LibreWolf не добавлена. Для общего компьютера это существенный незакрытый риск.
- Job Object с гарантированным kill-on-parent-close не реализован. Крестик окна PowerShell, TerminateProcess и выключение питания не являются управляемым выходом. Xray может остаться запущенным. Данная версия не готова к использованию на общем ПК как защищённый законченный продукт.
- Проверки процессов консервативны, зависят от прав CIM и поведения конкретной сборки Firefox. При недоступных данных могут удерживать lock из-за другого LibreWolf. Не заменяют проверенную изоляцию дерева процессов.
- Профиль, UUID и временные файлы лежат на SSD в открытом виде. Нет шифрования, автоматической очистки, безопасного стирания, удаления cookies или истории. File.Replace требует поддержки файловой системой; при ошибке нет delete-then-move обхода.
- Нет гарантии нулевых следов, очистки памяти, обхода администраторского контроля или системного kill switch. Разрешение имени узла может идти через DNS Windows; сетевой наблюдатель видит сервер, время и объём соединений.
- `about:policies` и `about:config`, соединения браузера, IP/DNS/WebRTC, остановка Xray, нормальный выход и аварийное закрытие требуют проверки дома без входа в аккаунты. Не все TCP-соединения браузера обязаны быть строго к 17890: есть также локальный IPC; важны необъяснённые внешние соединения.

- Источники схемы Xray прочитаны через официальный GitHub API по тегу v26.11.9.
- Синтаксис трёх рабочих скриптов и Test-Parser.ps1 проверяется сторонней грамматикой tree-sitter-powershell. Это не интерпретатор Windows PowerShell 5.1 и не замена исполнению тестов.
