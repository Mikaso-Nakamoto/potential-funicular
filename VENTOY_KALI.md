# Ventoy + Kali Linux Live: установка и запуск

Эта инструкция предполагает, что Ventoy **уже установлен** на флешке. Ventoy запускает ISO Kali, а программа запускается **вручную из терминала Kali**. Скрипты не являются загрузочным образом, не запускаются автоматически и не извлекают хеши с компьютера. Проверяйте только свои системы или системы, для которых у вас есть разрешение.

> Установка Ventoy на накопитель обычно стирает его содержимое. Если Ventoy уже работает, не устанавливайте его повторно и не форматируйте разделы. Если Ventoy ещё не установлен, сначала сделайте резервную копию и изучите [официальную инструкцию Ventoy](https://www.ventoy.net/en/doc_start.html).

## 1. Скопируйте Kali и проект на флешку

1. Подключите флешку Ventoy к работающему компьютеру. У Ventoy обычно есть большой раздел с данными, часто называемый `Ventoy`, и небольшой служебный раздел `VTOYEFI`. **Копируйте файлы на большой раздел данных**, не изменяйте `VTOYEFI`. Буква диска и метка могут отличаться.
2. Если Kali Live ещё нет на флешке, скачайте подходящий образ **Kali Linux Live**, например Live-образ для `amd64` на обычном ПК Intel/AMD, с [официальной страницы Kali](https://www.kali.org/get-kali/#kali-live). При необходимости проверьте контрольную сумму по инструкции Kali. Скопируйте ISO целиком на большой раздел Ventoy, например в папку `iso`. Распаковывать ISO не нужно.
3. Откройте [ветку проекта на GitHub](https://github.com/Mikaso-Nakamoto/potential-funicular/tree/arena/d6263d4c-potential-funicular), убедитесь, что выбрана именно эта ветка, и выберите **Code → Download ZIP**. Распакуйте архив и скопируйте папку проекта на большой раздел Ventoy. Для команд ниже назовите её `potential-funicular`. В ней должны лежать рядом `usb_audit.py` и `crack_with_hint.py`.
4. На большом разделе создайте отдельную папку `audit-data`. Поместите в неё заранее подготовленный файл `hashes.txt` с хешами **одного известного формата**. Можно также добавить свой `wordlist.txt`, по одному кандидату на строку. Для встроенного списка он не обязателен.

Пример расположения на разделе Ventoy:

```text
Ventoy/                             большой раздел данных
├── iso/kali-linux-…-live-amd64.iso
├── potential-funicular/
│   ├── usb_audit.py
│   ├── crack_with_hint.py
│   ├── README.md
│   └── VENTOY_KALI.md
└── audit-data/
    ├── hashes.txt                  подготовленные хеши
    └── wordlist.txt                необязательно
```

Для обычной проверки файл может содержать несколько записей одного формата. Для сценария `hint` нужна **ровно одна непустая запись**. Для строк `имя:хеш` далее используйте `--username`; NTLM и DCC2 нужно проверять отдельно, с правильным `--mode`. Синтаксис не определяет алгоритм автоматически.

## 2. Загрузите Kali через Ventoy

1. Оставьте флешку подключённой и перезагрузите компьютер. Откройте загрузочное меню компьютера и выберите USB-накопитель Ventoy; нужная клавиша зависит от устройства.
2. В меню Ventoy выберите файл Kali **Live ISO**. В меню Kali выберите вариант запуска **Live system**, а не установку системы на диск.
3. После загрузки откройте терминал. Пока Kali работает с загрузочной флешки, **не извлекайте её**.

Если USB или ISO не запускается, проверьте совместимость архитектуры, целостность ISO и настройки загрузки по документации Ventoy и производителя компьютера. Фактическую загрузку Ventoy/Kali Live на вашем оборудовании этот проект не проверял.

## 3. Найдите раздел данных и проверьте зависимости

Посмотрите устройства и точки монтирования, ничего не изменяя:

```sh
lsblk -o NAME,SIZE,FSTYPE,LABEL,MOUNTPOINTS
```

Найдите **большой раздел данных Ventoy** по метке, размеру и точке монтирования. Если он не смонтирован, откройте его в файловом менеджере Kali. Пример ниже — только пример: подставьте фактический путь из `lsblk`/файлового менеджера, сохранив кавычки:

```sh
VENTOY="/media/kali/Ventoy"
findmnt -T "$VENTOY" -o TARGET,SOURCE,FSTYPE,OPTIONS
ls -lh "$VENTOY/potential-funicular/usb_audit.py" "$VENTOY/potential-funicular/crack_with_hint.py"
```

Убедитесь, что `SOURCE` действительно относится к вашей флешке, а в `OPTIONS` есть `rw`. Если путь указывает на `overlay`/`tmpfs`, это может быть временная память Live-системы, а не раздел Ventoy. Если большой раздел недоступен для записи, не меняйте и не форматируйте его наугад: используйте другую доступную для записи флешку для данных либо заранее проверенное persistence-хранилище.

После проверки пути задайте каталог данных (или подставьте каталог на отдельном носителе):

```sh
DATA="$VENTOY/audit-data"
mkdir -p "$DATA"
findmnt -T "$DATA" -o TARGET,SOURCE,FSTYPE,OPTIONS
ls -lh "$DATA/hashes.txt"
```

Нужны Python 3.9+, Hashcat 6.2.6+ и совместимый вычислительный драйвер. Для `--cpu` требуется OpenCL-устройство типа CPU:

```sh
python3 --version
hashcat --version
hashcat -I
```

Наличие Hashcat и драйверов зависит от образа и оборудования. Если их нет и подключение к репозиториям Kali разрешено, можно установить вручную:

```sh
sudo apt update
sudo apt install python3 hashcat pocl-opencl-icd
```

Без persistence установленные в Live-систему пакеты обычно исчезают после перезагрузки. Без сети нужны заранее подготовленные совместимые программы и драйверы. Программа сама ничего не скачивает. Проверка версии и записи **не проверяет устройства OpenCL**:

```sh
python3 "$VENTOY/potential-funicular/usb_audit.py" --usb "$DATA" --check
```

`--check` также не подтверждает, что каталог находится именно на съёмном носителе или сохранится после перезагрузки. Если нужно проверить сохранность, создайте отдельный тестовый файл на выбранном разделе и убедитесь после перезагрузки, что он остался.

## 4. Необязательная проверка на демонстрационном хеше

Команды создают новый временный по имени каталог **на выбранном носителе**, не перезаписывая ваш `hashes.txt`. Пример использует только публичный тестовый MD5 пароля `password`:

```sh
DEMO=$(mktemp -d "$DATA/demo.XXXXXX")
printf '%s\n' '5f4dcc3b5aa765d61d8327deb882cf99' > "$DEMO/hashes.txt"
python3 "$VENTOY/potential-funicular/usb_audit.py" --usb "$DEMO" \
  --mode 0 --weak --show-passwords --cpu
```

При работающем CPU OpenCL ожидается одно совпадение и пароль `password`. Это проверка программы, не проверка пароля компьютера.

## 5. Запустите проверку своих подготовленных хешей

### Небольшой встроенный список

Для NTLM-хешей в `"$DATA/hashes.txt"`:

```sh
python3 "$VENTOY/potential-funicular/usb_audit.py" --usb "$DATA" \
  --mode 1000 --weak --show-passwords --cpu
```

Программа проверит встроенный список, например `1111`, `12345`, `00000`, `123456789` и `13243546`. При совпадении она покажет пароль и хеш в терминале. Уберите `--show-passwords`, чтобы не показывать пароли. Для входа `имя:хеш` добавьте `--username`. Для DCC2 используйте `--mode 2100` и формат DCC2; для других форматов — соответствующий режим из [README.md](README.md).

### Сценарий с подсказкой, словарём и маской

Для **одной** записи NTLM в `hashes.txt`:

```sh
python3 "$VENTOY/potential-funicular/usb_audit.py" hint --usb "$DATA" \
  --mode 1000 --hashes hashes.txt --mask '?d?d?d?d' --runtime 600 --cpu
```

Введите подсказку, когда программа спросит: ввод скрыт; пустая строка пропускает подсказку. Сначала проверяется подсказка, затем ограниченный набор её мутаций, словарь и указанная маска. При совпадении выводится `hash:plain`, а следующие этапы не запускаются. Если файл `wordlist.txt` отсутствует и свой словарь не задан, используется короткий встроенный список. Можно указать свой файл внутри `"$DATA"` через `--wordlist путь/словарь.txt`.

Маска `?d?d?d?d` проверяет **только четыре цифры**. Укажите свою маску, если нужен другой набор. Без `--mask` интерактивный запуск спросит маску после словаря; пустой ответ её пропустит. `--runtime 600` — лимит **каждого этапа Hashcat**, а не всего сценария; при ошибке или ограничении времени последующие этапы не запускаются, а результат помечается неполным. Для входа `имя:хеш` добавьте `--username`. Если нужно ввести режим и хеш с клавиатуры, уберите `--mode` и `--hashes` — программа их спросит.

## 6. Где результат и что важно

- Результаты находятся в `"$DATA"/audit-results/<дата>-<случайный_суффикс>/`. `report.json` содержит состояние и счётчики. Для обычного аудита `matched-hashes.txt` содержит совпавшие хеши; у сценария `hint` свой отчёт об этапах.
- Пароль в `hint` или с `--show-passwords` виден в терминале. По умолчанию программа не записывает связь хеш–пароль в отчёт или файл совпадений. Флаг `--save-plaintext` в сценарии `hint` дополнительно создаёт `cracked.txt` с этой связью. Терминальные журналы, драйверы и ОС также могут сохранять чувствительные данные.
- Большой раздел Ventoy нередко использует exFAT; права доступа POSIX на нём могут не защищать файлы. Ограничивайте физический доступ и по возможности используйте шифрованный носитель.
- Отсутствие совпадения не доказывает стойкость пароля: проверяются только заданные кандидаты и маски. Смотрите `run_complete` в отчёте и предупреждения в терминале.
- Путь `--usb` проверяется как каталог, но программа не определяет физическую съёмность. Сохранность данных и persistence нужно проверить самостоятельно.

Подробности о режимах, кодах выхода и конфиденциальности — в [README.md](README.md); дополнительная информация о Kali Live — в [KALI_LIVE.md](KALI_LIVE.md).
