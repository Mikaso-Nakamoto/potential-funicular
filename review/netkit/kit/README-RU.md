# LibreWolf-USB — браузер для колледжа, который ходит в интернет ТОЛЬКО через VPN

Портативный комплект на флешке: **LibreWolf** (форк Firefox с усиленной приватностью)
плюс **Xray-core** (клиент VLESS). Весь трафик браузера идёт через VPN по ключу
преподавателя; если VPN падает или вдруг появляется твой реальный IP — браузер
принудительно закрывается (**kill-switch**). После работы скрипт чистки убирает
пользовательские следы на ПК.

Что именно защищает и насколько — без округлений:

* **Браузер не имеет прямого пути в интернет**: прокси зашит в профиль, плюс
  `network.proxy.failover_direct=false` и `http3=false` — при мёртвом прокси
  запросы не «сваливаются» в прямое соединение (это была главная дыра до аудита).
* **Kill-switch без прав администратора — это не фильтр пакетов**, а закрытие
  процессов: firewall-правила скрипт ставит только если запущен от админа.
  Причина в том, что правила фильтрации Windows нельзя менять без прав.
* **«Следов нет» — неверно**: чистка убирает пользовательские записи, но на
  машине с доменным аудитом остаётся, что запускался PowerShell и что именно
  в нём было. Подробный список — в разделе «Что остаётся».

```
            ┌─ флешка ─────────────────────────────────────────────┐
            │  LibreWolf (профиль на флешке)                        │
            │      │  трафик браузера -> SOCKS 127.0.0.1:ПОРТ        │
            │      │  (порт выбирается заново при каждом запуске)     │
            │      ▼                                                │
            │  Xray (читает vpn\config.json — ключ VLESS)           │
            │      │  шифрованный туннель                           │
            └──────┼────────────────────────────────────────────────┘
                   ▼
              сервер VPN → интернет
```

Если туннель рвётся — у браузера просто **нет другого пути** в сеть (прокси зашит
в настройках профиля), а kill-switch дополнительно убивает процессы, если:

* процесс Xray умер;
* SOCKS-прокси перестал отвечать;
* через прокси вдруг стал виден **реальный IP** (главный признак утечки);
* VPN перестал отвечать несколько проверок подряд.

## Проверка перед выездом (30 секунд, без сети)

Двойной клик по `LibreWolf-USB.bat` → пункт 7. Скрипт не трогает сеть, реестр, брандмауэр и Xray —
он прогоняет шесть тестовых `vless://` ссылок (reality, ws+tls, httpupgrade, tcp+http,
grpc, IPv6) через конвертер, собирает из них конфиг и проверяет, что JSON парсится,
теги на месте, `alpn` пришёл массивом, а кавычка в `path` не ломает файл.

Увидел `ВСЁ ХОРОШО: N проверок пройдено` — можно ехать. Увидел `[FAIL]` — пришли
вывод, это быстрее, чем ловить проблему в колледже.

## Подготовка ДОМА (один раз, ~5 минут)

1. Скопируй папку `LibreWolf-USB` на флешку (или работай прямо с неё).
2. Запусти **`LibreWolf-USB.bat` → пункт 4** (двойной клик). Он:
   * скачает **LibreWolf portable** с официального GitLab (проверит sha256);
   * скачает **Xray-core** с официального GitHub;
   * спросит, откуда взять сервера, и предложит выбор:
     **[1] один ключ** — вставить `vless://` ссылку (можно несколько, тогда конфиг
     станет мульти-серверным), обновлять сервера придётся вручную;
     **[2] подписка** — вставить `https://.../sub/ТОКЕН`, тогда список серверов
     подтягивается с сервера провайдера и **обновляется сам** при запуске
     `LibreWolf-USB.bat` (если конфигу больше 3 дней).
3. Конвертер превратит ссылки в `vpn\config.json`. **Больше ссылки нигде
   вводить не надо** — они хранятся только в этом файле на флешке.

### Что значит «обновляется раз в 3 дня»

Это **не таймер и не расписание**. Таймера нет вообще: без ПК флешка ничего не делает.
Проверка происходит в тот момент, когда ты запускаешь `LibreWolf-USB.bat`, и звучит так:
«сколько дней назад изменялся `vpn\config.json`?»

| Возраст `config.json` на момент запуска | Что делает `LibreWolf-USB.bat` |
| --- | --- |
| меньше 3 дней | ничего не запрашивает, сразу работает |
| 3 дня и больше | поднимает туннель на текущем конфиге, **через него** обновляет подписку и перезапускает Xray с новым списком |
| месяц простоя | то же самое: увидит 30 дней и обновит на этом же запуске |

То есть «пропущенных» обновлений не бывает: если не запускал две недели — они
догонятся при первом же запуске. Порог нужен только чтобы не дёргать API при
каждом входе.

Обновить, не дожидаясь трёх дней (например, провайдер прислал новые сервера):

```
меню → пункт 3 «Обновить список серверов из подписки» (дома)
```

Пункт 3 пересобирает `vpn\config.json` и на этом заканчивается — браузер не
запускается. Вручную: `powershell -ExecutionPolicy Bypass -File app\update-sub.ps1`.

Если сайт открывается, но пустой (типичный случай — YouTube):

```
меню → пункт 2 → номер сервера (например, 1)
```

Это фиксирует ОДИН сервер и убирает балансировщик. Номер от 1 до числа серверов
в `config.json` (сколько их — видно в строке «серверов в config.json: N»).
Перебирай 1, 2, 3… и смотри, где работает.

Почему так: по умолчанию стоит `leastPing` — он выбирает сервер **на каждое
соединение**, поэтому одна страница грузится через разные выходные IP. YouTube и
Google такую пляску не переносят: часть запросов отваливается, страница остаётся
пустой. С одним сервером IP стабилен.

### Видео YouTube: встаёт загрузка при перемотке

Симптом: ролик начинает играть, но стоит перемотать — бесконечная загрузка, потом
«ошибка воспроизведения». На обычном ПК с VPN-клиентом тот же ролик играет в 1080p.

Причина та же, что и у пустой страницы: YouTube привязывает куски видео к одному
выходному IP, а балансировщик выдаёт новый узел на каждое соединение — при перемотке
запрос уходит через другой сервер, и Google отказывает.

Что делает сборка: видео-домены (`youtube.com`, `googlevideo.com`, `ytimg.com`,
`ggpht.com`, `youtube-nocookie.com`, `yt.be`) принудительно идут через `proxy-1` —
первый сервер конфига, — а весь остальной трафик продолжает балансироваться. Правило
добавляется и в уже собранный `config.json` при запуске сессии, пересобирать конфиг
не обязательно (в логе видно «добавлено правило: видео YouTube идёт через proxy-1»).

Если видео всё равно тормозит — первый сервер далеко или перегружен: пункт 10 покажет
задержку, пункт 2 позволит выбрать другой сервер на всю сессию.

Есть важное ограничение: обновление идёт **через уже поднятый туннель**. Если все
сервера в `config.json` умерли и туннель не встаёт — обновить подписку из колледжа
нельзя (запрос с токеном напрямую из чужой сети мы специально не пускаем). Тогда
дома: `powershell -ExecutionPolicy Bypass -File app\update-sub.ps1`.

### `vless://` и подписка — это две разные вещи

| | `vless://…` | `https://…/sub/ТОКЕН` |
| --- | --- | --- |
| Что это | **один сервер**, одна строка с ключом | **список серверов**, который отдаёт провайдер |
| Куда попадает при подготовке | сразу в `vpn\config.json` | в `vpn\config.json` + URL в `vpn\sub.txt` |
| Обновляется само | нет, надо заново вставлять ссылку | да: `LibreWolf-USB.bat` раз в ~3 дня обновляет **через туннель** |
| Если сервер умер | правь конфиг руками | подписка отдаст живой список |

Вставлять URL подписки в режим **[1]** бессмысленно: там ждут `vless://`, а не адрес
сайта — конвертер скажет «не удалось разобрать». И наоборот: `vless://` в режим
**[2]** тоже не подойдёт, ему нужен `https://`.

Если `config.json` уже есть, подготовка третий шаг пропускает. Обновить сервера
из подписки в этом случае:

```
powershell -ExecutionPolicy Bypass -File app\update-sub.ps1
```

> ⚠️ **Почему ссылку вставляют только дома:** при вставке в консоль ссылка
> проходит через буфер обмена. Дома это безопасно. В колледже ты её вообще
> не вводишь — уже готовый `config.json` читает сам `xray.exe`, файл нигде
> не открывается.

Если не хочется вставлять ссылку при подготовке — потом запусти дома в консоли:

```
powershell -ExecutionPolicy Bypass -File app\vless-to-config.ps1
```

**Никогда не открывай `vpn\config.json` двойным кликом / в блокноте на чужом ПК** —
это оставляет след в списке недавних файлов. Скрипты читают его сами.

## Работа в КОЛЛЕДЖЕ

1. Вставь флешку, открой папку `LibreWolf-USB`, запусти **`LibreWolf-USB.bat`** —
   откроется меню с логотипом; нажми **1** (или **2**, если нужен конкретный сервер —
   там же вводятся `-Fast` и прочие параметры).
2. Скрипт сам:
   * проверит, что `config.json`, `xray.exe` и `user.js` на месте, а сам `config.json`
     безопасен (только `socks` на 127.0.0.1, только `vless` + `tls`/`reality`, без
     прямых выходов наружу) — иначе откажется запускаться;
   * проверит сам ПК: не запрещены ли скрипты политикой PowerShell и не подсунуты ли
     браузеру политики Mozilla через реестр (тогда тоже откажется);
   * снимет переменные окружения, через которые чужой ПК может читать трафик
     (`MOZ_LOG`, `SSLKEYLOGFILE`, `HTTP(S)_PROXY` и подобные);
   * выберет **свободный случайный порт** и соберёт свою копию конфига в `%TEMP%`
     (на флешке `config.json` не меняется; после выхода копия удаляется);
   * запустит Xray (скрыто) и дождётся, пока поднимется SOCKS — с проверкой, что
     порт слушает именно наш Xray. Если владельца порта определить нельзя,
     запуск отменяется: лучше не работать, чем отдать трафик чужому процессу;
   * **до запуска браузера** проверит внешний IP через VPN — если он совпадает
     с реальным или не определяется, браузер **не запустится вообще**;
   * включит kill-switch и запустит LibreWolf (профиль — на флешке). В kill-switch
     добавлена проверка соединений самого браузера: если LibreWolf попробует
     соединиться не с 127.0.0.1, то есть мимо прокси, сессия сразу прерывается —
     это ловится раньше, чем сменится внешний IP;
   * что бы ни случилось (ошибка, отказ, Ctrl+C в консоли), Xray будет остановлен,
     правила брандмауэра сняты, сессионный конфиг удалён — «осиротевшего»
     `xray.exe` не останется.
3. Работай. Окно консоли **не закрывай** — в нём живёт kill-switch.
4. Закрой браузер. Скрипт остановит VPN и напишет, что сессия чистая.
5. Запусти **`LibreWolf-USB.bat` → пункт 6**, дождись отчёта, потом вытаскивай флешку.

Если kill-switch сработал (мигание + сообщение + браузер закрылся) — значит
туннель оборвался. Проверь интернет и запусти `LibreWolf-USB.bat` заново.

## Несколько серверов и автопереключение

Конфиг — мульти-серверный (как в методичке): все `vless://` ссылки становятся
outbound'ами `proxy-1`, `proxy-2`, ..., а **балансировщик `leastPing`** гоняет
весь трафик через самый быстрый живой сервер (проверка каждые 3 минуты через
`observatory`). Один сервер умер — Xray сам переключит на другой, без перезапуска.

Важно: правило маршрутизации отправляет в балансировщик **весь** трафик
(tcp+udp). Прямого пути (fallback на `direct`) нет вообще — если умерли ВСЕ
серверы, соединения просто не открываются, а kill-switch закроет браузер.
Это не баг, это защита.

## Подписка Happ: обновление серверов

Ссылки подписки живут недолго — серверы меняются. Обновление работает **в двух
режимах**:

**Автоматически, в колледже (через туннель).** Если на флешке есть `vpn\sub.txt`
и конфигу больше 3 дней, `LibreWolf-USB.bat` сам обновит ключи:

```
старый ключ поднял VPN
   -> запрос к api.giont.ru идёт ЧЕРЕЗ VPN (колледж видит только шифрованный
      туннель до VPN-сервера, SNI api.giont.ru наружу не торчит)
   -> свежий список vless:// ссылок
   -> vpn\config.json пересобран, xray перезапущен
   -> IP проверен заново; если новый конфиг не заработал — автокат на прежний
```

Запрос уходит через балансировщик `leastPing`, то есть через самый живой
сервер на данный момент. Единственное ограничение: если старые ключи УЖЕ мертвы
и туннель не поднимается — обновиться в колледже нельзя (принципиально: прямой
запрос к API с колледжного ПК показал бы сети колледжа, что ты пользуешься
этим VPN-сервисом). Тогда — домой.

**Вручную, дома (напрямую):**

```
powershell -ExecutionPolicy Bypass -File app\update-sub.ps1
```
(или `python app\update-sub.py`, если Python удобнее)

Скрипт:
* возьмёт URL подписки и hwid из `vpn\sub.txt` (при первом запуске спросит и сохранит);
* скачает список ссылок с заголовками клиента (`User-Agent`, `x-hwid`) — поэтому
  в приложении твоё устройство **не отображается** как подключённое;
* распакует base64 (в т.ч. без паддинга и url-safe), отбросит дубли и битые узлы;
* соберёт новый `vpn\config.json` (старый сохранит в `config.bak.json`).

`vpn\sub.txt` — такой же секрет, как `config.json`: не открывать на чужих ПК,
флешку не терять и не одалживать.

## Грязные ПК: правила безопасности

Ты работаешь на машинах, где **до тебя** мог поработать другой студент по
инфобезу. Правила (как на лекции):

1. **Никаких реальных аккаунтов.** Не входи в свою почту, соцсети, госуслуги,
   банковские приложения из этого браузера. Аккаунты Firefox выключены в
   `user.js` (`identity.fxaccounts.enabled = false`), синхронизации нет.
2. **Не сохраняй пароли в браузере.** Запоминание паролей выключено
   (`signon.rememberSignons = false`): профиль на флешке, и если флешку
   скопируют — сохранённые пароли уйдут вместе с ним.
3. **Не вводи реальные пароли с клавиатуры чужого ПК вообще** — кейлоггер
   перехватит их до любого шифрования. Этот браузер — для рабочего трафика
   по методичке, не для личных логинов.
4. **Всё, что лежит на флешке, может быть скопировано** скомпрометированным
   ПК: `config.json`, `sub.txt`, профиль. Поэтому: не теряй флешку, не давай
   никому, держи в кармане, а не на столе.
5. Вставил флешку — увидел лишние/неизвестные файлы в комплекте — не запускай
   ничего, дома проверь комплект (сравни с эталонным zip).

**Чистка сразу после браузера.** Закрыл окно LibreWolf — скрипт замечает это примерно
за 3 секунды, пискнет и спрашивает: чистить ли следы этой сессии. `Y` — чистит обычным
набором (то же, что пункт 6 без флагов), `N` — оставляет, 60 секунд без ответа —
пропускает. Только после этого гасится Xray и снимаются правила брандмауэра: в конце
видно «VPN выключен».

Пока браузер открыт, скрипт раз в ~30 секунд пишет «…жду закрытия браузера (процессов
LibreWolf: N). Если он уже закрыт — нажми q». Клавиша **q** заканчивает сессию сразу,
не дожидаясь, пока исчезнут все процессы. Если процессы LibreWolf уже не читаются по
пути, они определяются по имени — закрытие замечается и в этом случае.

Строка «IP через VPN сменился» пишется не чаще раза в минуту (с числом смен): при
балансировщике выходной IP меняется часто, и раньше консоль превращалась в поток
таких строк. Если закрыть окно консоли раньше браузера, Xray останется
до перезагрузки — при следующем запуске меню его процессы и правила брандмауэра
убираются автоматически (строка «Хвосты прошлой сессии убраны»).

Если запуск шёл из скрипта (ввод перенаправлен), вопрос не задаётся и VPN гасится сразу.

## Насколько защищён токен подписки

Коротко: файл `vpn\config.json.enc` без пароля не читается — это обычный AES-256,
а не «спрятано». Но насколько это непробиваемо, решает **только пароль**.

**Что защищено:**
- `vpn\config.json`, `vpn\config.json.bak.json`, `vpn\sub.txt` под паролем лежат
  как `*.enc`: PBKDF2-HMAC-SHA256, 200 000 итераций → AES-256-CBC + HMAC-SHA256
  (сначала шифрование, потом MAC; MAC сверяется за постоянное время).
- Открытые копии с флешки удаляются сразу после шифрования.
- Сессионные копии (`%TEMP%\lwusb-…\config.json`, `sub.txt`, логи xray) теперь
  затираются случайными байтами и удаляются в конце сессии — раньше каталог оставался.
- URL подписки и `x-hwid` не передаются аргументами командной строки; после вставки
  ссылки буфер обмена очищается.
- Логи не содержат ни ключей, ни ссылок, ни внешних IP (`loglevel=none`), пункт 7
  это проверяет.

**Чего это не даёт** (честно):
- **Пароль — единственная защита.** Соль и проверочный MAC лежат в самих файлах,
  поэтому перебор идёт офлайн, без флешки-оригинала. 200 000 итераций на обычном ПК —
  это доли секунды, на видеокарте — десятки тысяч паролей в секунду. Отсюда:
  - пароль вида «Москва2024», «qwerty123», слово+цифры — подбирается за минуты-часы;
  - 10-12 случайных символов (буквы обоих регистров, цифры, знаки) — годы на одной
    видеокарте;
  - фраза из 4-5 случайных слов («паром-улитка-стена-7») — практически нереально.
  Поэтому при задании пароля скрипт требует минимум 10 символов и предупреждает,
  если пароль короткий или словарный.
- Пока сессия идёт, конфиг расшифрован в `%TEMP%`; при штатном выходе он затирается,
  при выдёргивании флешки/сбросе питания — может остаться.
- Удалённые файлы на SSD гарантированно не затираются, теневые копии Windows и журнал
  ФС скрипт не чистит.
- Если флешку взяли вместе с подсмотренным паролем — защиты нет.

**Если флешку потеряли:** перевыпустить подписку в кабинете провайдера (старый токен
перестанет работать), затем дома запустить пункт 3 — конфиг соберётся заново.
Забытый пароль восстановить нельзя: ключи считаются потерянными.

## Профиль, реальные аккаунты и расширения

**Можно ли держать в этом браузере свои реальные аккаунты** (например, Яндекс Телемост
под рукой, а поиск — в приватном окне)? Технически можно, но это меняет модель угроз.

Что при этом остаётся:
- трафик идёт через туннель, на ПК колледжа не остаётся истории, кэша и следов;
- WebRTC выключен, QUIC выключен, DNS уходит в туннель, пароли не сохраняются;
- ключи (`config.json`, `sub.txt`) можно закрыть паролем.

Что ломается:
- **аккаунт сам привязывает вас к личности.** Яндекс/Google знают, кто вы, и видят,
  что вход был с VPN-адреса. Анонимности больше нет — но её и не было, если вы
  входите в свой аккаунт.
- **профиль на флешке становится ценнее ключей.** Cookie сессии Телемоста/Яндекса —
  это готовый вход в аккаунт без пароля. Профиль не шифруется (в нём тысячи мелких
  файлов, шифровать их на каждом запуске дорого). Флешку потеряли — потеряли сессию.
  Лечится сменой пароля в аккаунте, не шифрованием.
- **смешивание**: если этим же профилем смотреть что-то, что не должно быть связано
  с вашим именем, cookie и отпечаток браузера вас свяжут.

Практичное правило: этот профиль — для сервисов, где вы **не против** быть узнанным
(учёба, Телемост, рабочая почта). Для «посмотреть, что не должно быть связано со мной» —
приватное окно (Ctrl+Shift+P): своя сессия, cookie не сохраняются после закрытия.
Личные аккаунты с деньгами и почтой лучше держать в обычном браузере на домашнем ПК,
а не на флешке, которая ездит в колледж.

**Расширения.** В комплекте их нет специально: каждое расширение — это лишний
отпечаток и лишний код с доступом к вашим страницам. Что имеет смысл поставить:
- **uBlock Origin** — блокировка рекламы и трекеров, главный выигрыш по скорости
  и приватности. Ставится один раз в профиль на флешке;
- **ClearURLs** — вырезает `utm_*` и прочие метки из ссылок;
- больше ничего не нужно. Не ставьте «ускорители», «VPN-расширения», переводчики
  со доступом ко всем страницам и любые расширения, которые просят «читать данные
  на всех сайтах» без необходимости.

Помните: `user_pref` из `user.js` важнее настроек расширений — при каждом запуске
файл копируется в профиль заново, так что настройки самого браузера сбрасываются,
а расширения и их данные остаются.

## DNS и DNS через HTTPS (DoH)

DNS — это «телефонная книга»: по имени сайта находит его IP. Обычный DNS-запрос идёт
открытым текстом (порт 53), и его видит тот, кто раздаёт интернет.

DoH — тот же запрос, но упакованный в HTTPS на порт 443. Снаружи выглядит как обычный
сайт, провайдер не видит, какие имена вы спрашиваете.

**В этом комплекте DoH не нужен и намеренно выключен** (`network.trr.mode = 5`):
имена резолвит не ваш ПК, а VPN-сервер (`socks_remote_dns = true`), потому что запрос
уходит в SOCKS вместе с именем. То есть провайдер и сеть колледжа не видят даже самих
имён — DoH тут ничего не добавит, а включение добавило бы лишний канал к Cloudflare
мимо логики туннеля.

Включать DoH имеет смысл только без VPN: например, в обычном браузере дома, если
провайдер подменяет ответы DNS.

## Пинг серверов

Пункт **10** в меню: задержка до каждого сервера из `vpn\config.json` (TCP-подключение
к адресу и порту, без ICMP и без прав администратора). Показывает миллисекунды, красит
по порогам и подсказывает, какой номер брать в пункте 2.

Пока браузер открыт, пинг печатается сам **раз в 30 секунд**:
`[пинг 14:52:03] 1: 42 мс   2: 96 мс   3: нет ответа`. Нажать пинг вручную в любой
момент — клавиша **p**, затем Enter.

## Пароль на ключи: как включить

Пароль закрывает `vpn\config.json` (UUID узлов) и `vpn\sub.txt` (URL подписки с токеном):
на флешке остаются только `secret.dat` (соль и проверочный HMAC, самого пароля там нет)
и файлы `*.enc`. Без пароля соединение не поднимается.

**Как задать:**
1. Дома запусти `LibreWolf-USB.bat` и выбери пункт **1** (или 2).
2. Скрипт спросит: «Поставить пароль на ключи этой флешки?» — нажми **Enter** или **Y**.
3. Введи пароль дважды (минимум 10 символов; лучше 4-5 случайных слов). Каждый символ показывается звёздочкой,
   Backspace стирает, Esc отменяет; второй ввод — подтверждение.

   **Раскладка.** Пароль вводится теми же символами, что при задании: русские буквы
   и латинские — разные пароли, регистр тоже важен. Если пишет «неверный пароль»,
   первым делом проверь RU/EN и Caps Lock — это самая частая причина.
4. Скрипт зашифрует `config.json` и `sub.txt`, удалит открытые копии и сразу продолжит запуск.

Дальше при каждом запуске пунктов 1 и 2: строка «Пароль флешки» → ввод → туннель
поднимается. Неверный пароль — три попытки, потом отказ: браузер не запускается,
xray не стартует. Закрыл окно, открыл заново — пароль снова.

**Что это стоит:** около 0,2 секунды на проверку пароля при запуске. Скорость туннеля
не меняется: Xray читает расшифрованную копию из `%TEMP%`, которая удаляется при выходе.

**Что важно знать:**
- Пароль нигде не хранится. Забыли — `config.json` и `sub.txt` не прочитать: дома
  заново ввести ссылки (пункт 4) и перевыпустить подписку в кабинете (пункт 3).
- Пункты 3 и 4 (только дома) тоже спросят пароль: они читают и переписывают те же файлы.
- Пункты 5, 6, 7 (архив, чистка, проверка) работают без пароля.
- Смена пароля пока не автоматизирована: расшифровать старым вручную и задать новый —
  скажите, добавлю отдельным пунктом меню.

## Что именно чистит меню, пункт 6

* логи сессий на флешке (`vpn\logs\`);
* в `TEMP` колледжного ПК — папки/файлы с именами librewolf/xray;
* историю Win+R (записи с нашими именами);
* MuiCache реестра (память «дружественных имён» запущенных программ);
* **UserAssist** реестра (журнал запуска программ, записи закодированы ROT13 —
  скрипт декодирует и удаляет **только наши** записи);
* отчёты об ошибках Windows (WER), связанные с нами;
* историю команд PowerShell (только наши строки);
* правила брандмауэра `LibreWolf-USB-KILLSWITCH*`, если их успел поставить
  kill-switch (без этого следующий запуск браузера был бы заблокирован навсегда);
* сбрасывает кэш DNS.

С `-Deep` (нужен запуск от администратора) дополнительно удаляются Prefetch-файлы
`LIBREWOLF*.pf` и `XRAY*.pf`. Чужие записи не трогаются: счётчики
`cmd.exe`/`powershell.exe` и Prefetch `FIREFOX*.pf` остаются — это следы других
людей на общей машине, и стирать их нельзя ни по смыслу, ни по правилам.

Режимы:

```
меню, пункт 6                 — обычная чистка (права пользователя)
меню → пункт 6 → `-Deep`           — + Prefetch LIBREWOLF*/XRAY* (нужен администратор)
меню → пункт 6 → `-Scrub`          — + полностью стереть профиль браузера на флешке
                             (история/куки; config.json остаётся)
```

Глубокий режим (нужны права администратора — в колледже обычно нет, поэтому
отдельно и осознанно):

```
powershell -ExecutionPolicy Bypass -File "<буква флешки>:\LibreWolf-USB\app\clean-traces.ps1" -Deep
```

`-Deep` дополнительно чистит Prefetch и сбрасывает счётчики запуска
cmd/powershell в UserAssist.

### Что остаётся на ПК даже после чистки (честно)

**Пользовательские следы:**

* `HKCU\...\Explorer\MountPoints2` — факт подключения **этой** флешки (буква тома);
* списки недавних документов, если ты открывал что-то с флешки в проводнике или блокноте;
* Prefetch для `CMD.EXE`/`POWERSHELL.EXE` — видно, что с флешки что-то запускали;
* на диске ПК нет ни профиля браузера, ни логов: они живут на флешке (кэш браузера
  отключён, работает только из ОЗУ).

**То, что видит администратор домена/сети (и не убирается без его прав):**

* `Amcache.hve` и `BAM/DAM` — какие `.exe` запускались, когда и с какого пути;
* SRUM (`SRUDB.dat`) — сетевой трафик по процессам;
* журнал событий: **4688** (запуск процесса) и **4104** (полный текст запущенного
  PowerShell-скрипта, если включён script-block logging);
* история Windows Defender / EDR: что сканировалось и что попало в карантин;
* логи сети колледжа: факт TLS-соединения с VPN-сервером, объём и время трафика
  (содержимое — нет, но сам факт «здесь ходили в VPN» виден).

Если на машине включён аудит, содержимое `start.ps1` остаётся в журнале, и обойти
это без прав администратора нельзя. Комплект этого и не обещает — он снижает
локальные следы для следующего пользователя, а не делает тебя невидимым.

Хочешь нулевую историю на флешке — раз в неделю дома запускай меню → пункт 6 → `-Scrub`
или просто удаляй папку `profile\`.

## Частые вопросы

**Это точно methodology-safe? Ключ нигде не светится?**
Ссылка вводится один раз дома. `config.json` лежит на флешке, на колледжном ПК
его никто не открывает: его читает только `xray.exe` напрямую (как в методичке).
Логи Xray на флешку больше не пишутся: `loglevel: none`, а сырой вывод Xray идёт
в `%TEMP%`. На флешке остаётся только журнал сессии (`vpn\logs\session-*.log`)
без адресов серверов и без IP; его чистит `LibreWolf-USB.bat` → пункт 6.

**Что если я случайно открою config.json на чужом ПК?**
Закрой блокнот, запусти `LibreWolf-USB.bat` → пункт 6 — он сотрёт запись из списков недавних
файлов не полностью (недавние документы чистятся только фильтром по нашим
именам — блокнот пишет своё). На будущее: просто не открывай.

**Прокси «сбросился» в настройках браузера?**
`app\user.js` перезаписывается при каждом запуске и заново зашивает
SOCKS 127.0.0.1 (порт выбирается случайно и дописывается в профиль при старте),
а `failover_direct=false` не даёт браузеру уйти напрямую при мёртвом прокси. Но если **руками** переключить прокси в `about:config`,
браузер пойдёт напрямую: kill-switch увидит это только на очередной проверке IP
(~30 секунд) и затем закроет браузер. Это окно существует — не трогай настройки
сети в браузере во время сессии.

**LibreWolf-USB.bat отказался запускаться: «политики Mozilla» или «политика ПК запрещает скрипты».**
Первое — на ПК прописаны политики Firefox (`HKLM/HKCU\Software\Policies\Mozilla`):
они могут подсунуть браузеру прокси или расширение помимо `user.js`. На **своём**
ПК это лечится `LibreWolf-USB.bat -IgnorePolicies`, на чужом — не запускай.
Второе — PowerShell в режиме `ConstrainedLanguage` или политика `Restricted`:
в таком режиме проверки порта и kill-switch не работают, поэтому запуск отменяется
целиком (обойти это без прав администратора нельзя).

**При подготовке вылезло `curl: option -K: found an unknown config option` / `config file option ... is unknown`.**
Это баг версии комплекта от 15.11.2026 (первая половина дня): секреты передавались
`curl` через stdin, а Windows PowerShell 5.1 портит такой ввод. Исправлено —
перекачай свежий архив `LibreWolf-USB-fixed.zip` (версия от 15.11.2026; md5 указан рядом со ссылкой на скачивание)
и запусти `LibreWolf-USB.bat` → пункт 4 ещё раз: `vpn\sub.txt` с твоим URL уже сохранён,
URL вводить заново не нужно.

**В кабинете провайдера «5 из 5 устройств», и подписка отдаёт нули.**
Лимит считается по **устройствам** (`x-hwid`), а не по IP-адресу: запрос с того же
домашнего IP без «своего» HWID — для панели новое устройство, и вместо серверов
она отдаёт заглушку `0.0.0.0`. Что помогает: (1) удалить в кабинете/боте лишние
устройства — освободить слот; (2) взять HWID одного из оставшихся (в Happ —
настройки/«о приложении») и записать его в `vpn\sub.txt` — тогда панель видит
знакомое устройство и слот не тратится. HWID должен быть **один и постоянный**,
иначе каждое обновление подписки занимает новый слот.

**Подписка скачалась, но «нет валидных узлов» и в предупреждениях `0.0.0.0`.**
Панель вернула **заглушку** вместо адреса сервера. Комплект такие узлы не берёт:
с адресом `0.0.0.0` Xray не подключится ни при каком TLS, а `security=none` означает
туннель без шифрования. Проверь `vpn\sub.txt` (`url` вида https://…/sub/ТОКЕН, `hwid` непустой) и перевыпусти подписку в кабинете
подписки и предложит ввести `x-hwid`, если его не было. Если и с HWID адреса нет:
спроси у провайдера прямую ссылку `vless://` с адресом и портом и вставь её в
`app\vless-to-config.ps1`.

**`LibreWolf-USB.bat` → пункт 6 чистит кэш Windows?**
Частично, и честно: то, что оседает на диске — да, оперативную память — нет.

Чистится: миниатюры и значки проводника (`thumbcache_*`/`iconcache_*`), ярлыки
«Недавних файлов», ведущие на флешку, записи списка недавних документов в
реестре, временные файлы наши (`lwusb-*`, включая профиль от `-Fast`), логи
сессий, Prefetch (с `-Deep` и правами администратора), история Win+R, MuiCache,
UserAssist, WER, история PowerShell, кэш DNS.

НЕ чистится: файловый кэш в оперативной памяти — тот самый, из-за которого
второй запуск быстрее первого. Командой без администратора его не сбросить,
на диск он не пишется и исчезает при выключении ПК. Если нужен «холодный»
старт — это перезагрузка машины, а не скрипт.

**Как обновлять комплект, не теряя браузер, настройки и темы.**
В архиве обновления лежат ТОЛЬКО скрипты и документация. Чего в нём нет:
`app\LibreWolf\` (сам браузер), `vpn\xray.exe`, `vpn\sub.txt`, `vpn\config.json`
и папки `profile`. Поэтому распаковка поверх папки на флешке заменяет десяток
маленьких файлов и ничего не ломает:
- темы, закладки, расширения, пароли страниц, история — всё это лежит внутри
  `profile\` (`prefs.js`, `extensions\`, `chrome\`, `places.sqlite`) и не входит в архив;
- браузер и Xray остаются теми же — пункт 4 пропускает уже установленное
  (`-Force` заставит переустановить, это затронет только `app\LibreWolf\`);
- подписка и ключи не трогаются — `vpn\config.json` в архив не кладётся.

Перезапись ~85 КБ для флешки безопасна, ресурс не расходуется заметно.

Единственное исключение: `profile\user.js` перезаписывается при каждом запуске
из `app\user.js` — это настройки прокси и защит, их правка в профиле не сохраняется.
И не запускай пункт 6 с `-Scrub`: этот ключ стирает профиль целиком (историю и входы).

**Можно обновить частично — профиль, темы и входы останутся.**

Чего нет в архиве, то и не перезаписывается никогда: `profile\` (темы, закладки,
расширения, история, входы), `app\LibreWolf\`, `vpn\xray.exe`, `vpn\config.json`,
`vpn\sub.txt`, `vpn\secret.dat` и `*.enc`.

Два рабочих способа:

**Способ 1 — распаковать поверх (по шагам).** «Поверх» значит «в ту же папку на
флешке, где уже лежат `LibreWolf-USB.bat` и `app`», а не в новую папку.

1. Скачай `LibreWolf-USB-fixed.zip` и подключи флешку.
2. Открой флешку в Проводнике: «Этот компьютер» → твоя флешка. В корне уже лежат
   `LibreWolf-USB.bat`, `app`, `profile`, `vpn`, `_download`.
3. Двойным щелчком открой скачанный zip — Проводник покажет его как обычную папку.
4. Внутри zip выдели всё: `Ctrl+A`, затем `Ctrl+C`.
5. Переключись в окно флешки (её корень) и вставь: `Ctrl+V`.
6. Windows спросит про замену файлов — выбери **«Заменить файлы в папке
   назначения»**, поставь галочку «Выполнять это действие для всех файлов» и нажми «Да».
7. Проверь, что в корне флешки осталось: `LibreWolf-USB.bat`, `README-RU.md`,
   `app`, `profile`, `vpn`, `_download`. Никакой новой папки появиться не должно.

**Частая ошибка:** распаковка создаёт внутри флешки лишнюю папку
(`LibreWolf-USB-fixed\app\...`). Тогда в корне лежит старый батник, а новый
комплект — в подпапке, и обновление «не работает». Лечится так: открыть эту
подпапку, выделить всё (`Ctrl+A`), вырезать (`Ctrl+X`) и вставить в корень флешки
с заменой.

**Как понять, что обновление применилось:** запусти `LibreWolf-USB.bat` — в правом
верхнем углу рамки меню написан номер сборки, например `F-64`. Он должен совпасть
с тем, что написано в описании релиза, откуда ты качал архив.

**Способ 2 — перетащить только скрипты**: открыть в архиве `app\` и скопировать
с заменой все `.ps1` и `user.js`, плюс `LibreWolf-USB.bat` в корень флешки.

Что важно обновить в `app\`, если обновляете выборочно:

| файл | зачем |
|---|---|
| `menu.ps1` | новые пункты (9 — проверка IP, 10 — пинг) и справка |
| `start.ps1` | пинг в сессии, чистое закрытие, мягкий watchdog, пароль |
| `vless-lib.ps1` | функция замера задержки `Measure-ServerPing` |
| `update-sub.ps1` | шифрование при обновлении подписки, очистка буфера |
| `self-check.ps1` | 55 проверок (секреты в логах, прямой IP, плоский результат пинга) |
| `secret.ps1` | новый файл: пароль на ключи (появился в F-60) |
| `ping-servers.ps1` | новый файл: пинг серверов (появился в F-61) |

Проверить после обновления: пункт 7 — «ВСЁ ХОРОШО: 55 проверок пройдено».

**Хочу один готовый архив, где уже всё внутри.**
Запусти `LibreWolf-USB.bat` → пункт 5 на флешке, где уже есть браузер и Xray. Рядом
появится `LibreWolf-USB-full-ДАТА.zip` — в нём скрипты, браузер, Xray и
`vpn\config.json`. Профиль, логи и `_download\` в архив не попадают. Такую
сборку можно распаковать на другую флешку и сразу работать, без интернета.

Сборка содержит `vpn\sub.txt` (URL подписки с токеном) и `vpn\config.json`
(ключи узлов) — её нельзя никому передавать и нельзя выкладывать в облака.
Нужен архив без секретов: меню → пункт 5 → `-NoSecrets` — тогда на новой
флешке ключ или подписку придётся ввести заново.

**`LibreWolf-USB.bat` → пункт 4 качает браузер заново, хотя он уже есть.**
Теперь не качает: если `app\LibreWolf\LibreWolf.exe` и `vpn\xray.exe` на месте,
шаги пропускаются. Принудительно переустановить: меню → пункт 4 (переустановка: пункт 4 с `-Force`).

**Всё дико тормозит: проводник на флешке, браузер, выделение файлов с задержкой.**
Это флешка, а не VPN. Профиль браузера — это десятки тысяч мелких файлов,
и на медленной флешке (особенно USB 2.0) каждая операция ждёт диск.
Два шага:

1. Отдельного замера флешки в меню больше нет (он был в прошлых версиях). Практика: если второй запуск быстрый, дело в кэше ОС, а не в VPN.
2. Меню → пункт 8 «Ускорить флешку и проводник»: замеряет, где именно тормозит,
   и настраивает обновление значков, индексирование и кэш под флешку.
   и терпи задержки.

Что уже сделано в комплекте, чтобы меньше писать на флешку: диск-кэш браузера
выключен (кэш только в ОЗУ), сохранение сессии — раз в 5 минут вместо 15 секунд,
сетевой предиктор выключен. Поэтому флешка не так сильно нагружается, а задержки
проводника остаются только при просмотре папок.

Что ещё помогает: синий порт USB 3.0 вместо передней панели, режим
«Подробности» вместо «Крупные значки» (эскизы не строятся), не держать окно
проводника на флешке во время работы браузера, добавить букву флешки
в исключения антивируса.

**Браузер открывается через минуту, уже после «VPN остановлен», и пишет «proxy server is refusing connections».**, уже после «VPN остановлен», и пишет «proxy server is refusing connections».**
Виноват был лончер: `librewolf.exe` в корне папки запускает настоящий процесс и
сам сразу завершается, а скрипт принимал это за закрытие браузера и гасил Xray.
Исправлено: сессия следит за всеми процессами браузера и за lock-файлом профиля.
Просто дай браузеру догрузиться (с флешки это до 20-60 секунд) и не запускай
`LibreWolf-USB.bat` второй раз.

**В браузере «The proxy server is refusing connections».**
Значит браузер стучится не в тот порт, который открыл Xray. В окне LibreWolf-USB.bat
прокрути вверх до строки `SOCKS-порт этой сессии: N`, затем в браузере:
`about:config` -> `network.proxy.socks_port` (должно быть то же N) и
`about:support` -> Profile Folder (должен быть путь вида
`<флешка>:\...\Browser\profile`). Если путь другой — браузер открылся со
своим профилем: закрой ВСЕ окна LibreWolf и запусти LibreWolf-USB.bat снова.

**`LibreWolf-USB.bat` мигнул и закрылся, ничего не показав.**
Это был баг версии до 15.11.2026 (символ `|` в строке баннера — для cmd это
конвейер, и файл обрывался раньше `pause`). Исправлено, перекачай архив.
Если что-то мигает и в будущем: открой `cmd`, выполни `cd /d E:\LibreWolf-USB`,
затем `LibreWolf-USB.bat` — окно останется и текст ошибки будет виден.

**Можно ли открыть сайт без VPN?**
Нет. Без работающего Xray браузер не может открыть ни один сайт — так и задумано.

**Почему обновление подписки не сработало, хотя конфигу больше 3 дней?**
Три причины по частоте: (1) нет `vpn\sub.txt` — конфиг собран из `vless://` ссылок,
тогда авто-обновления нет вообще; (2) туннель не поднялся на старом конфиге — обновление
возможно только через живой туннель; (3) панель провайдера привязала токен к IP —
тогда запрос из VPN-выхода отклоняется. Во всех трёх случаях `LibreWolf-USB.bat` продолжает
работу со старым конфигом, ничего не ломается.

**Обновление LibreWolf/Xray?**
Дома удали папки `app\LibreWolf` и `vpn\xray.exe`(+`*.dat`) и запусти
`LibreWolf-USB.bat` → пункт 4 снова (config.json останется, ссылку заново вводить не надо).
Скачивание проверяет целостность: у LibreWolf сверяется `sha256` с суммой рядом
с файлом, у Xray — `digest` из GitHub API (или `.sha256` релиза). Если контрольную
сумму получить не удалось, подготовка **останавливается** и печатает фактический
хеш: сверь его на странице релиза и запусти снова с `-AllowUnverified`.

Версию Xray можно прибить (воспроизводимость вместо «всегда последняя»):

```
powershell -ExecutionPolicy Bypass -File app\prepare-home.ps1 -XrayVersion v25.10.1

Если контрольную сумму скачать не удалось, подготовка теперь **останавливается**:
непроверенный архив с браузером или `xray.exe` в комплект не попадает. Сверь
sha256 вручную на странице релиза и запусти ещё раз так:

powershell -ExecutionPolicy Bypass -File app\prepare-home.ps1 -AllowUnverified
```

**Обновить сервера VPN (ссылки подписки)?**
Дома: `powershell -ExecutionPolicy Bypass -File app\update-sub.ps1` — скачает
свежий список из подписки и пересоберёт config.json (старый — в config.bak.json).

**Чем отличается `update-sub.py` от `update-sub.ps1`?**
Ничем по возможностям: обе версии собирают один и тот же конфиг (tcp с http-заголовком,
ws, grpc, httpupgrade, tls и reality, `flow`, `alpn`, `spiderX`) и обе валидируют
JSON перед записью. Python-версия — запасная, если дома удобнее Python.

**Почему в приложении подписки моё устройство не видно?**
Скрипт обновления ходит в API напрямую с заголовками клиента (`User-Agent`,
`x-hwid`), а не из самого приложения — для сервера это «клиент без GUI»,
в списке устройств приложения оно не отображается.

**Комплект сам обновляет ключи в колледже?**
Да: если есть `vpn\sub.txt` и конфигу больше 3 дней, `LibreWolf-USB.bat` скачает
свежую подписку **через уже поднятый туннель**, пересоберёт конфиг, перезапустит
xray и перепроверит IP (при сбое — откат на прежний конфиг). Если старые ключи
вообще мертвы — туннеля нет, обновление невозможно: только дома.

**Легально ли это?**
Сам по себе комплект — обычный приватный браузер и обычный VPN-клиент, и в
Германии пользоваться личным VPN законно. Отдельно проверь два пункта:
правила заведения (AUP/Network Policy: там часто прямо запрещены VPN,
сторонний софт с флешек и «обход фильтрации») и правила сервиса подписки
(заголовки `User-Agent`/`x-hwid`, которыми комплект представляется клиентом
Happ, скрывают устройство из панели провайдера — это может нарушать его условия).
Решение остаётся на тебе, но знать об этом надо заранее, а не после разговора
с сисадмином.

## Требования

* Windows 10 1803+ / Windows 11, 64-бит (для Xray-windows-64; LibreWolf тоже x64);
* ~1.5 ГБ свободного места на флешке (браузер ~350 МБ + профиль);
* в колледже: запуск .bat с флешки не должен быть заблокирован политикой
  (обычно не заблокирован). Если PowerShell режется AppLocker'ом — комплект
  не запустится, это ограничение нельзя обойти честно.

*Собрано по методике преподавателя: конфиг по ключу, на чужой машине не открывается; при утечке реального IP — блокировка; после работы — чистка следов.*
