# kit-secret — парольная защита ключей VPN на флешке

Шифрование `vpn\config.json` (UUID узлов) и `vpn\sub.txt` (URL подписки с токеном) паролем, который знает только владелец флешки.

Совместимость: **Windows PowerShell 5.1** (.NET Framework 4.7.2+, есть на любом Win10 1809+/Win11) и **PowerShell 7+**. Проверено на Linux/macOS PowerShell 7.

---

## Модель угроз: чужая машина

Скрипт рассчитан на работу **с флешки на чужом компьютере** — учебный класс, библиотека, компьютер знакомых. Это меняет требования сильнее, чем «защита потерянной флешки».

### От чего защищает

| Угроза | Как закрыто |
| --- | --- |
| Кража или потеря флешки | Всё содержимое шифруется PBKDF2-HMAC-SHA256 (600 000 итераций) → AES-256-CBC + HMAC-SHA256 |
| Другой пользователь машины читает файлы после вашего ухода | На носителе только `.enc`; открытый текст не пишется на флешку вообще |
| Кто-то подменяет заголовок контейнера | MAC покрывает `iters`, `prf`, `salt`, `iv` (AAD) — подмена ломает файл, а не «ускоряет/замедляет» чтение |
| Случайное подтверждение опасного действия | Вопросы да/нет: **Enter = НЕТ**, по умолчанию отказ |
| Подсмотреть длину пароля через экран | Звёздочки печатаются группами по 4 символа, остаток добивается — точная длина не видна |

### От чего НЕ защищает — читать обязательно

- **Вредоносная программа или администратор на машине, пока скрипт работает.** Они видят память процесса, нажатия клавиш, могут подменить сам `secret.ps1`. Никакой скрипт это не лечит — нужна доверенная машина.
- **Старые незашифрованные копии.** Если `config.json` уже лежал на флешке открытым текстом, `Remove-Item` на FAT32/exFAT только освобождает кластеры: файл восстанавливается `photorec`/`testdisk`. Скрипт больше **не создаёт** таких файлов, но прошлые не стирает. Флешку следует отформатировать на доверенной машине.
- **Имена файлов, размеры, даты.** Не скрываются.
- **Хардварный кейлоггер** между клавиатурой и ПК.
- **Сон/гибернация.** Если закрыть крышку с расшифрованными ключами в памяти, дамп уйдёт в `hiberfil.sys` на диск **чужой машины**.

## Как это устроено

```
vpn\secret.dat     kit-secret/2
                   iters, prf, salt, check
                   check = HMAC-SHA256(check_key, "kit-secret-check/2")
                   Пароль не хранится — только верификатор.

vpn\*.enc          kit-enc/2
                   iters, prf, salt, iv, mac, data(base64)
                   mac = HMAC-SHA256(mac_key,
                           "kit-enc/2\niters=..\nprf=..\nsalt=..\niv=.."  ← AAD
                           || iv || ciphertext)
```

Ключи: PBKDF2-HMAC-SHA256, **96 байт** = `enc(32) | mac(32) | check(32)`. Три независимых ключа — разделение доменов: верификатор пароля не переиспользует MAC-ключ.

Порядок при расшифровке: **сначала MAC, потом AES**. Обратный порядок дал бы padding oracle.

### Обратная совместимость

`kit-secret/1` и `kit-enc/1` читаются: 64 байта ключа, MAC по `iv||ciphertext` без AAD, `prf` по умолчанию SHA1 (поведение старого `Rfc2898DeriveBytes`). Перешифровка — `Update-KitContainer` / `Update-KitSecret`.

## Проверки, заложенные в код

Все они fail-closed — при любой аномалии возвращается `$null`, а не «попробуем как-нибудь»:

- размер файла проверяется **до** чтения (32 МиБ на контейнер, 16 МиБ на исходник);
- длина base64 ограничена до `FromBase64String`;
- `salt` ровно 16 байт, `iv` ровно 16, `mac` ровно 32, `data` кратно 16 и ≥ 16;
- `iters` в диапазоне 1000…2 000 000;
- `prf` только `SHA1` / `SHA256`; `SHA1` допустим только для v1;
- дублирующийся ключ в заголовке — отказ целиком;
- заголовок контейнера должен точно совпадать с ожидаемым (`kit-enc/1` или `kit-enc/2`).

## Установка и использование

```powershell
# один раз: задать пароль (интерактивно, звёздочками)
. .\secret.ps1
Show-KitThreatModel          # что защищено, а что нет — на общей машине полезно прочитать
Set-KitPassword -Vpn 'E:\vpn'   # вернёт $true; сам пароль наружу не отдаётся

# при каждом подключении
$pw = Read-KitPassword -Vpn 'E:\vpn'        # до 3 попыток, '' при отказе
if (-not $pw) { throw 'Без пароля ключи недоступны' }

# расшифровать в память и не писать на флешку
$bytes = Unprotect-KitBytes -EncPath 'E:\vpn\config.json.enc' -Password $pw
try {
    $json = [Text.Encoding]::UTF8.GetString($bytes)   # работаем с $json
} finally {
    Clear-KitBytes $bytes                              # занулили
}

# зашифровать обратно
$plain = [Text.Encoding]::UTF8.GetBytes($json)
Protect-KitBytes -Plain $plain -Password $pw -Target 'E:\vpn\config.json.enc'
# массив $plain зануляется внутри Protect-KitBytes

# обслуживание
Update-KitContainer -EncPath 'E:\vpn\config.json.enc' -Password $pw   # v1 -> v2
Update-KitSecret    -Vpn 'E:\vpn' -Password $pw                       # secret.dat v1 -> v2
```

> `Unprotect-KitFile` / `Protect-KitFile` (работа с путями) оставлены для совместимости, но **на флешке их использовать не нужно**: они пишут открытый текст на носитель. Для флешки — только `*Bytes`.

## Тесты

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\test-kit-secret.ps1
```

33 проверки, включая эталонные векторы, посчитанные **независимо** (Python `hashlib.pbkdf2_hmac` + `pycryptodome` AES-CBC):

| Вектор | Значение |
| --- | --- |
| enc-ключ (PBKDF2-SHA256, 600k, 96 байт) | `091991bd…47b290` |
| mac-ключ | `01b591cc…28ed51` |
| check-ключ | `e5f65a14…424286` |
| AES-CBC шифртекст | `kZDcsA87…TzYo` |
| MAC с AAD (v2) | `8a0e3f65…93e10d` |
| MAC без AAD (v1) | `e8b9763b…0f1639` |

Смысл в том, что тест ловит не «код совпал сам с собой», а расхождение с независимой реализацией: если поменяется формат AAD, порядок байтов или параметры PBKDF2 — тест упадёт.

Отдельно проверяется: подмена `iters` и `salt` обнаруживается, дубль ключа отвергается, пустой и короткий пароль отвергаются, `Clear-KitBytes` действительно зануляет, `kit-enc/1` читается, `-Upgrade` переводит в v2 и файл остаётся читаемым.

## Что осталось непроверенным

Честно: **тесты в этой среде не запускались** — PowerShell здесь не установлен, скачать релиз нельзя. Проверено статически: парность скобок, соответствие формата AAD (сверено с независимой реализацией), все эталоны посчитаны Python-кодом. Перед использованием на флешке запусти тесты у себя:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\test-kit-secret.ps1
```

Если какой-то `Check` упал — не используй скрипт, пришли вывод.
